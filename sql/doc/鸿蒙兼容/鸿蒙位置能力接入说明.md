# 鸿蒙位置能力接入说明

## 文档目标

- 本文档只处理 `shengyu-ui/shengyu-ui-admin-uniappx` 在 HarmonyOS 下的位置查看与定位能力接入。
- 目标是把 `uni-openlocation`、定位权限、验证路径一次写清楚，后续可直接按文档开工。

## 已确认的官方口径

### 1. `uni.openLocation` 不是内置直连能力

- `uni-app x` 官方文档明确说明：
  - App 端的 `openlocation` 是一个独立的 `UTS` 插件
  - 需要前往插件市场导入 `uni-openlocation`
- 官方文档链接：
  - `uni.openLocation(options) @openlocation`
  - https://doc.dcloud.net.cn/uni-app-x/api/open-location.html

### 2. HarmonyOS 额外要求定位权限

- 同一份官方文档明确说明：
  - HarmonyOS 调用 `uni.openLocation` 需要申请
    - `ohos.permission.APPROXIMATELY_LOCATION`
    - `ohos.permission.LOCATION`
  - 需要自行在项目中配置权限

### 3. 鸿蒙侧 `uni-location` 模块仍要保留

- `uni-app x` 鸿蒙平台配置文档说明：
  - provider 机制的定位模块仍需手动添加
  - manifest 中使用 `app-harmony -> distribute -> modules -> uni-location -> system`
- 官方文档链接：
  - `鸿蒙平台配置`
  - https://doc.dcloud.net.cn/uni-app-x/collocation/manifest-harmony.html

### 4. 如果要在 UTS 插件里声明鸿蒙权限，要用 `module.json5`

- `UTS for HarmonyOS` 官方文档说明：
  - 可以在 `utssdk/app-harmony/module.json5` 中声明 `requestPermissions`
  - 字符串原因说明放在 `utssdk/app-harmony/resources`
- 官方文档链接：
  - `uts for HarmonyOS`
  - https://doc.dcloud.net.cn/uni-app-x/plugin/uts-for-harmony.html

## 正式接入步骤

### 第一步：导入 `uni-openlocation`

- 按官方要求，从 DCloud 插件市场导入 `uni-openlocation`
- 导入后重点检查：
  - 项目内是否生成对应 `uni_modules`
  - 插件是否带有 `app-harmony` 目录
  - 插件是否已经自带 Harmony `module.json5`

### 第二步：核对权限声明是否真实存在

- 如果导入后的插件已经带了 Harmony `module.json5`，检查其中是否声明了：
  - `ohos.permission.APPROXIMATELY_LOCATION`
  - `ohos.permission.LOCATION`
- 如果插件没有声明，不要假定“会自动有”。
- 这时应选择其一：
  - fork 插件并补齐 `module.json5`
  - 自建一个很薄的 Harmony UTS 包装层，为 `openLocation` 专门声明权限

## `module.json5` 参考结构

下面的结构不是直接来自 `uni-openlocation` 插件源码，而是基于 `UTS for HarmonyOS` 官方文档整理出的工程模板，用于你们 fork 或自建包装插件时参考：

```json
{
  "module": {
    "type": "har",
    "deviceTypes": [
      "default",
      "tablet",
      "2in1"
    ],
    "requestPermissions": [
      {
        "name": "ohos.permission.APPROXIMATELY_LOCATION",
        "usedScene": {
          "when": "inuse"
        },
        "reason": "$string:permission_location_reason"
      },
      {
        "name": "ohos.permission.LOCATION",
        "usedScene": {
          "when": "inuse"
        },
        "reason": "$string:permission_location_reason"
      }
    ]
  }
}
```

配套资源字符串可放在：

- `utssdk/app-harmony/resources/base/element/string.json`

例如：

```json
{
  "string": [
    {
      "name": "permission_location_reason",
      "value": "用于查看聊天位置卡片和地图定位"
    }
  ]
}
```

说明：

- 上面的 `module.json5` 与 `string.json` 路径、字段结构是按 `UTS for HarmonyOS` 官方文档整理的工程模板。
- 真正落地时，需要以实际导入的 `uni-openlocation` 插件结构为准。
- 如果插件已有同名资源，不能重复冲突。

## 工程验收清单

### 配置验收

- `manifest.json` 中确认保留：
  - `app-harmony.distribute.modules.uni-location.system`
  - `app-harmony.distribute.modules.uni-map.tencent`
- 导入的 `uni-openlocation` 在 Harmony 产物侧确认有权限声明。

### 客户端状态验收

- 设置页鸿蒙状态区应满足：
  - `位置查看` 显示已接入
  - `定位权限` 在授权后显示已授权
  - `系统定位` 在系统打开后显示已开启

### 功能验收

- 聊天页位置卡片点击可正常打开地图
- 位置选择页可正常取当前定位
- 地图页面可正常查看位置
- 当权限拒绝时，设置页状态能真实反映为未授权
- 当系统定位关闭时，设置页状态能真实反映为已关闭

## 风险提示

- 不能只看 `uni.openLocation` 编译不报错，就判断鸿蒙已经接好了。
- 也不能只看 `manifest` 有 `uni-location` 模块，就判断 `openLocation` 一定可用。
- 真正要看三层：
  - 插件是否已导入
  - 鸿蒙权限是否已声明
  - 真机上权限与系统定位开关是否真实开启
