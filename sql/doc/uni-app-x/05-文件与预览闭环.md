# 05 文件与预览闭环

本章目标：在本项目内形成“打开任意文件”的统一链路与可执行标准，覆盖：

- 入口统一（聊天/聊天文件/搜索等）
- 预览策略统一（后端 open-strategy 决定 PREVIEW/DOWNLOAD）
- 下载与打开（downloadFile + openDocument）
- WebView 在线预览
- cache 与 user_data 的边界、清理策略
- 平台差异与权限合规

## 5.1 现状（仓库对齐）

### 5.1.1 核心落点

- 统一预览页：`shengyu-ui/shengyu-ui-admin-uniappx/pages/common/file-preview.uvue`
- 文件后端 API：`shengyu-ui/shengyu-ui-admin-uniappx/api/file.uts`
  - `getFileOpenStrategy(fileId, expirationSeconds)`
- 下载与打开工具：`shengyu-ui/shengyu-ui-admin-uniappx/utils/file.uts`
  - `downloadAndOpenDocumentWithRetry(url, loadingTitle)`
- 路由收敛：`shengyu-ui/shengyu-ui-admin-uniappx/utils/nav.uts`
  - `navToFilePreview({ fileId, url, name })`

### 5.1.2 已完成的入口统一（当前状态）

- `pages/message/chat.uvue`：文件消息点击已改为 `navToFilePreview(...)`
- `pages/message/chat-files.uvue`：非图片/视频点击已改为 `navToFilePreview(...)`，并优先使用 `file.fileId`

## 5.2 规范（Principles）

- **单入口**：所有“打开文件”行为必须跳转到 `pages/common/file-preview.uvue`。
- **fileId 优先**：能拿到 `fileId` 时必须传 `fileId`，由后端策略决定预览/下载。
- **页面不拼逻辑**：
  - 页面不得散落 `downloadFile + openDocument` 组合逻辑，必须走 `utils/file.uts`。
  - 页面不得散落拼接 `/pages/common/file-preview?...`，必须走 `utils/nav.uts`。
- **跨端边界明确**：
  - H5 不支持 `openDocument`，H5 侧应走浏览器或 web-view。
  - `openDocument` 作为“兜底打开方式”，在线预览优先走 web-view（策略允许时）。

## 5.3 打开文件的统一数据模型（项目建议）

建议统一“打开文件请求”的数据结构（示意）：

- `fileId`：后端文件标识（优先）
- `url`：可访问的下载地址（fallback）
- `name`：展示名
- （可选）`mime/ext/size/source`：用于埋点与策略兜底

落地方式：

- 页面只负责组装最小字段并调用 `navToFilePreview(...)`
- `file-preview` 负责调用策略与执行预览/下载

## 5.4 统一预览页（file-preview）职责边界

文件：`pages/common/file-preview.uvue`

### 5.4.1 入参

- `fileId`：存在时调用 `getFileOpenStrategy`
- `url`：仅当没有 `fileId` 时使用（直接下载打开）
- `name`：用于展示（当前页面暂未用于标题，可后续扩展）

### 5.4.2 策略执行

- `getFileOpenStrategy(fileId)` 返回：
  - `action: 'PREVIEW' | 'DOWNLOAD'`
  - `previewUrl?: string`
  - `downloadUrl: string`
  - `message?: string`

执行规则：

- `action === 'PREVIEW' && previewUrl`：使用 `web-view` 打开 `previewUrl`
- 否则：使用 `downloadUrl` 走“下载打开”
- 失败提示：`errorMsg` + “重试/下载打开”

## 5.5 下载与打开（utils/file.uts）规范

文件：`utils/file.uts`

### 5.5.1 统一入口

- `downloadAndOpenDocumentWithRetry(url, loadingTitle)`

关键行为（当前实现）：

- H5：优先 `window.open(url, '_blank')`，规避 XHR/CORS 与 `openDocument` 不支持问题。
- App：
  - `uni.downloadFile(url)` 获取 `tempFilePath`
  - `uni.openDocument({ filePath: tempFilePath, showMenu: true })`
  - 异常弹窗提示，可无限次重试（用户选择）

### 5.5.2 cache 与持久化

- `downloadFile` 默认落 cache（可被系统清理），不得当作可靠持久化。
- 如需二次打开加速：应扩展 `utils/file.uts`，引入
  - `USER_DATA_PATH` 落盘
  - 本地索引（`fileId -> localPath + lastAccessAt + size`）
  - 清理策略（按大小/时间的 LRU）

## 5.6 WebView 在线预览（web-view）规范

- web/小程序：web-view 全屏限制（页面只能显示一个铺满的 web-view）。
- App：
  - 4.0 起默认宽高 100%；若在滚动容器中使用要评估嵌套滚动差异。
- 本地 HTML：必须放 `/static`（非 static 不会被打包）。

对项目建议：

- 在线预览优先走后端 `previewUrl`，避免端侧拼接第三方预览服务规则。

## 5.7 权限与合规（与文件能力相关）

- “文件预览/下载”多数在沙盒内完成，不应为了文件能力额外申请不必要权限（避免审核风险）。
- 若涉及相册/系统文件访问：需按 Android API Level 适配媒体权限，并在 App 全局统一做用途提示（可参考权限监听 API）。

## 5.8 Reviewer Checklist

### 5.8.1 禁止项

- 页面直接拼 `/pages/common/file-preview?...`
- 页面直接调用 `uni.openDocument` / 组合 `uni.downloadFile + uni.openDocument`
- 新增文件打开入口但不走 `file-preview`（破坏统一入口）

### 5.8.2 必须项

- 新增文件打开入口：必须调用 `navToFilePreview(...)`
- 能传 `fileId` 就必须传 `fileId`
- H5 分支不得调用 `openDocument`

### 5.8.3 推荐项

- 为 `file-preview` 增加“复制链接/分享/保存到本地”等能力前，先明确：
  - 落点目录（cache vs user_data）
  - 权限触发点与用途提示
  - 清理策略

## 5.9 常见问题（Troubleshooting）

- **打开失败/网络异常**：优先检查下载是否成功、是否被代理/证书拦截；使用重试弹窗确认可恢复。
- **H5 无法打开**：确认走了 `window.open` 分支；检查 URL 是否可直接被浏览器访问。
- **下载后找不到文件**：cache 可能被系统清理；需要持久化则落 `USER_DATA_PATH`。
- **web-view 无法加载本地页面**：确认资源在 `/static`，并检查路径大小写。
