# 多语言国际化开工前核对清单

## 文档关系

- 本文档是从属清单，服务于主文档：
  - `sql/doc/多语言国际化设计任务文档.md`
- 本文档不定义新口径，只负责把开工前需要确认的事项 checklist 化。

若本清单与主文档冲突，以主文档为准。

## 0. 2026-04-21 最终口径

- `shengyu-ui-admin-uniappx`、`shengyu-ui-admin-vue3`、`shengyu-ui-platform-vue3` 三端语言统一按当前设备/浏览器本地缓存，不再设计用户级 `language_mode`
- 后端继续只消费当前请求 `Accept-Language` 与 WebSocket `locale`，用于返回当前设备语言下的系统提示、错误文案、系统消息渲染结果
- `system_users.language_mode` / `platform_users.language_mode` 方案已废弃，本清单中凡涉及“用户语言偏好落库”的历史项，均以下述新口径替代理解

## 1. 总体核对

- 是否已确认本次国际化覆盖三类前端：
  - `shengyu-ui-admin-uniappx`
  - `shengyu-ui-admin-vue3`
  - `shengyu-ui-platform-vue3`
- 是否已确认“用户原始内容不翻译，系统消息才国际化”这条红线
- 是否已确认主文档为唯一总设计入口
- 是否已确认 SQL 草案、key 规范、开工清单都回链主文档

## 2. DBA / 数据库核对

- 是否确认 `platform_error_code_i18n` 作为平台级表，不带 `tenant_id`
- 是否确认 `system_notify_template_i18n` 作为租户级表，带 `tenant_id`
- 是否确认软删除字段、索引命名、字符集规范与当前库一致
- 是否确认无需新增用户级语言字段，旧 `language_mode` 如已加过需纳入回收 SQL

## 3. 后端平台核对

- 是否确认 HTTP 统一解析 `Accept-Language`
- 是否确认使用 `LocaleContextHolder` 作为请求语言上下文
- 是否确认 `GlobalExceptionHandler` 进入国际化改造范围
- 是否确认 `ServiceExceptionUtil` 进入国际化改造范围
- 是否确认 Bean Validation 文案进入国际化改造范围
- 是否确认错误码翻译查询与缓存能力由后端统一提供
- 是否确认后端不持久化用户语言，只依赖当前请求语言上下文

## 4. 移动端核对

- 是否确认设置入口为 `我 -> 设置 -> 多语言`
- 是否确认首期只支持：
  - `跟随系统`
  - `简体中文`
  - `English`
- 是否确认移动端请求层统一发送 `Accept-Language`
- 是否确认 `uni.setLocale` 与现有 `store/locale.uts` 共同生效
- 是否确认原生标题 / TabBar / 页面文案都进入改造范围

## 5. 租户 Web 端核对

- 是否确认当前 `vue-i18n + element-plus locale` 继续保留
- 是否确认 axios/request 层补 `Accept-Language`
- 是否确认语言按浏览器本地缓存，不做登录后服务端语言恢复
- 是否确认个人中心不再承载 language preference 更新能力

## 6. 平台 Web 端核对

- 是否确认当前 `vue-i18n + element-plus locale` 继续保留
- 是否确认 axios/request 层补 `Accept-Language`
- 是否确认语言按浏览器本地缓存，不做平台用户语言持久化
- 是否确认平台个人中心不再承载 language preference 更新能力

## 7. IM / 通知核对

- 是否确认系统消息使用 `eventKey + params`
- 是否确认老历史系统消息不做破坏性回刷
- 是否确认用户原始聊天内容保持原文
- 是否确认 WebSocket 认证阶段补 `resolvedLocale`
- 是否确认通知模板翻译按租户隔离

## 8. 开工顺序核对

- 是否先做后端平台底座
- 是否先落请求语言解析、消息资源与系统消息结构化
- 是否在协议稳定后再做 IM 系统消息国际化
- 是否避免“先大面积改页面，最后才补后端协议”
