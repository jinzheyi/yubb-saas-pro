# 群单聊设置页面设计任务文档

## 最终设计决议

- 群聊设置页与单聊设置页的消息设置统一为两个开关：
  - `消息免打扰`
  - `置顶聊天`
- 这两个开关必须接入现有会话主链路，不允许只做页面本地态：
  - 前端统一走 `conversationService`
  - 后端统一走 `PUT /system/im/conversation/update`
  - 多端一致统一依赖 `GET /system/im/conversation/sync`
- 群聊设置页保留两个核心入口：
  - `群文件`
  - `聊天记录`
- 单聊设置页保留两个核心入口：
  - `文件`
  - `聊天记录`
- 群聊的 `群文件` 与单聊的 `文件` 只是入口叫法不同，打开后统一进入同一个文件总览页。
- 统一文件总览页复用 `shengyu-ui/shengyu-ui-admin-uniappx/pages/message/chat-files.uvue`，页面内统一提供四个 tab：
  - `全部`
  - `图片`
  - `视频`
  - `文件`
- 统一文件总览页的数据口径按会话维度处理：
  - 单聊按当前 `chatId` 查询当前会话中的图片、视频、文件消息
  - 群聊按当前 `chatId` 查询当前群会话中的图片、视频、文件消息
- 页面标题按入口场景动态展示：
  - 群聊入口显示 `群文件`
  - 单聊入口显示 `文件`
- `聊天记录` 页统一复用 `shengyu-ui/shengyu-ui-admin-uniappx/pages/message/chat-history.uvue`

## 设计原则

- 会话设置必须服从单一状态源：
  - 会话列表页 `shengyu-ui/shengyu-ui-admin-uniappx/pages/message/message.uvue` 只消费 `conversationService` 的会话状态
  - 设置页修改成功后，也必须回到同一份会话状态，不能出现第二套状态源
- 微信 / 企业微信风格对齐原则：
  - `置顶聊天` 影响会话列表分组与排序
  - `消息免打扰` 不阻断消息接收，只影响提醒呈现与未读展示样式
  - 设置修改后当前端立即生效，且换端、重进、增量同步后不得回滚
- 入口命名遵循业务语义：
  - 群聊强调“群文件”
  - 单聊强调“文件”
- 打开后的页面交互尽量统一，减少用户学习成本与维护成本
- 文件总览页按会话消息维度展示，避免群聊、单聊逻辑分叉后出现功能不一致
- `im_group_file` 继续保留，作为群文件业务索引与后续企业微信式群文件管理能力的承载基础；但当前设置页打开的统一文件总览页不再依赖它作为唯一展示来源

## 当前系统真实链路基线

### 1. 会话页状态源

- 会话列表页：`shengyu-ui/shengyu-ui-admin-uniappx/pages/message/message.uvue`
- 会话数据统一来自：`shengyu-ui/shengyu-ui-admin-uniappx/services/conversation-service.uts`
- UI 工作方式：
  - 首屏优先读 `messageService.getConversations()` 本地缓存，快速渲染
  - 随后调用 `conversationService.loadConversations()`
  - `conversationService` 内部优先走 `GET /system/im/conversation/sync?cursorVersion=&limit=`
  - 服务层 merge 完成后，通过 `addUpdateListener` 通知消息页全量刷新
- 消息页表现规则：
  - `isPinned = true` 的会话进入置顶区并优先排序
  - `noDisturb = true` 的会话显示免打扰图标
  - `noDisturb = true` 且有未读时，显示红点而不是数字 badge

### 2. 设置变更前后端链路

- 前端接口：
  - `shengyu-ui/shengyu-ui-admin-uniappx/api/conversation.uts`
  - `PUT /system/im/conversation/update`
  - body 字段：
    - `chatId`
    - `isPinned`
    - `noDisturb`
- 前端服务：
  - `conversationService.pinConversation(chatId, isPinned)`
  - `conversationService.setMute(chatId, noDisturb)`
- 后端入口：
  - `AppImConversationController#updateConversation`
- 后端服务：
  - `ImConversationServiceImpl#updateConversation`
  - 先更新 `im_chat_user`
  - 再写入 `im_conversation_user_state`
  - 同时分配新的 `cursorVersion`

### 3. 已有能力与约束

- 已有：
  - 会话更新接口已存在
  - `isPinned / noDisturb` 已进入 `AppImConversationRespVO`
  - `/conversation/sync` 已返回会话用户态字段
  - 前端消息页已按 `isPinned / noDisturb` 做展示和排序
- 约束：
  - 设置页必须更新 `chatId` 维度的会话，而不是 `targetId / groupId` 维度的页面临时变量
  - 单聊页入口当前只传 `chatId`，因此设置页必须先从会话服务反查 `targetId`
  - 群聊页若仅持有 `groupId`，必须通过 `get-by-target` 反查出 `chatId`

## 现状结论

- 前端层面：
  - 群聊设置页已经具备 `消息免打扰 / 置顶聊天` 开关
  - 单聊设置页原先还是本地 `ref`，未接真实会话接口，需要统一并轨
- 后端层面：
  - 权威设置入口应是 `updateConversation`
  - `pinConversation(Long userId, Long conversationId, Boolean isPinned)` 与 `setMute(Long userId, Long conversationId, Boolean noDisturb)` 两个 service 方法仅改 `im_chat_user`，不承担完整跨端同步闭环
  - 因此前端不得把“只改库字段、不推进用户态版本”的内部简化方法当成最终落地方案

## 本轮实施范围

- 调整单聊设置页：
  - 将 `置顶 / 新消息通知` 统一为：
    - `置顶聊天`
    - `消息免打扰`
  - 页面加载时根据 `chatId` 回填真实会话设置
  - 页面切换开关时走会话服务与后端真实接口
  - 资料区不再使用硬编码展示
  - 删除顶部未开发的图片/文件/链接/搜索快捷区
  - 增加 `文件` 入口
  - 保留 `聊天记录` 入口
- 调整群聊设置页：
  - `消息免打扰 / 置顶聊天` 统一走会话服务
  - 页面 `onShow` 时补刷一次会话设置，避免返回页面状态过期
  - 保留 `群文件` 入口
  - 保留 `聊天记录` 入口
- 改造 `chat-files.uvue`：
  - 支持通过入口参数区分显示 `群文件` 或 `文件`
  - 统一按 `chatId` 展示全部/图片/视频/文件四个 tab
  - 长按/更多操作统一提供 `下载`、`转发`
  - `转发` 复用现有消息转发链路
  - `下载` 需兼容 Android、iOS、Web：
    - 图片/视频在移动端保存到相册
    - 普通文件在移动端下载后调用系统打开
    - Web 端优先触发浏览器下载，失败再回退新窗口打开
- 补充后端统一媒体查询接口：
  - 按 `chatId` 查询当前会话内的图片、视频、文件消息
  - 支持 tab 类型过滤

## 后端真实落地要求

### P0. 设置接口必须成为权威入口

- 前端所有 `置顶聊天 / 消息免打扰` 修改统一调用：
  - `PUT /system/im/conversation/update`
- 不允许形成多条语义重叠但一致性能力不同的设置入口
- `updateConversation` 必须保证：
  - 更新 `im_chat_user.is_pinned / no_disturb`
  - 同步写入 `im_conversation_user_state`
  - 推进 `cursorVersion`
  - 推进或保持正确的 `conversationVersion`
  - 后续端侧可通过 `/conversation/sync` 拉到最新设置

### P0. 跨端一致性闭环必须成立

- 设置成功后，当前端立即生效只是第一层
- 真正完成落地还必须满足：
  - 同账号多端能收到这次会话状态变更
  - 断网重连后 `/conversation/sync` 能恢复该状态
  - 重进消息页排序和免打扰 icon 不回滚
- 推荐服务端补齐：
  - 在 `updateConversation` 成功后，向当前用户所有在线 WS 连接推送 `SYSTEM_NOTIFY`
  - payload 至少透传新的 `cursorVersion`
  - 端侧收到后按既有逻辑触发 `syncConversationsIncrementally(false)`

### P0. 用户态版本语义不允许被破坏

- 不允许改动以下字段既有权威语义：
  - `cursorVersion`
  - `conversationVersion`
  - `lastReadSequence`
  - `lastMessageSequence`
- 其中：
  - `cursorVersion` 负责用户维度增量拉取游标
  - `conversationVersion` 负责同 chat 快照合并的幂等与乱序保护

## 有序推进方案

### 第一阶段：前端设置页并轨

- 群聊设置页、单聊设置页全部统一走 `conversationService`
- 返回消息页后立即体现：
  - 置顶分组变化
  - 免打扰图标变化
  - 未读样式变化

### 第二阶段：后端设置闭环核实

- 核对 `AppImConversationController#updateConversation`
- 核对 `ImConversationServiceImpl#updateConversation`
- 核对 `im_conversation_user_state` 是否正确写入：
  - `cursor_version`
  - `conversation_version`
  - `is_pinned`
  - `no_disturb`
- 核对 `/conversation/sync` 返回项是否带出最新设置

### 第三阶段：多端同步补强

- 若当前 `updateConversation` 后没有 WS 通知：
  - 补推 `SYSTEM_NOTIFY`
  - 透传 `cursorVersion`
- 端侧复用现有增量同步逻辑，不另起一套设置同步专线

### 第四阶段：联调验收

- 单聊设置修改后返回消息页，UI 立即变化
- 群聊设置修改后返回消息页，UI 立即变化
- 同账号第二端在线时，能自动同步设置变化
- 杀进程重进后设置不丢失
- 离线一段时间后重连，`sync` 后状态不回滚

## 明确不做

- 群聊设置页不新增额外的 `文件` 入口
- 单聊设置页不复活顶部快捷功能入口
- 当前轮次不扩展独立的“群文件库管理页 / 文件夹 / 收藏 / 管理员操作台”
- 当前文档不把 `消息免打扰` 扩展为系统级推送策略中心，仅处理会话级免打扰
- 当前文档不新增独立 `置顶会话列表接口`，仍以现有会话列表 / 增量同步结果为权威

## 验收标准

- 单聊设置页与群聊设置页均显示统一文案：
  - `消息免打扰`
  - `置顶聊天`
- 设置页切换后，不必手动刷新，返回会话页立即可见结果：
  - 置顶聊天进入置顶区
  - 取消置顶后回到普通会话区
  - 免打扰会话显示免打扰 icon
  - 免打扰会话未读按红点规则展示
- 群聊设置页点击 `群文件` 后，进入统一文件总览页，显示 `全部/图片/视频/文件`
- 单聊设置页点击 `文件` 后，进入同一文件总览页，显示 `全部/图片/视频/文件`
- 群聊与单聊点击 `聊天记录` 后，均进入统一聊天记录页
- 统一文件总览页中的 `下载`、`转发` 在 Android、iOS、Web 三端具备可用路径
- `PUT /system/im/conversation/update` 成功后，`GET /system/im/conversation/sync` 能返回该变更
- 同账号多端或重登后，`消息免打扰 / 置顶聊天` 状态不回滚
- 后端编译通过，前端入口无死链、无明显布局残留
