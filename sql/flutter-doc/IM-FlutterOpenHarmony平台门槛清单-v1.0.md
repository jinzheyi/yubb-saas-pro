# IM Flutter OpenHarmony 平台门槛清单 v1.0

> 文档日期：2026-04-29  
> 文档定位：OpenHarmony 进入正式交付前必须通过的平台基线、P0 能力门槛与验收证据清单

---

## 1. 目标

本文件用于回答一个实际工程问题：

OpenHarmony 什么时候可以从“文档已准备好”升级为“可以作为正式移动端目标开工和验收”。

结论不是靠口头判断，而是靠门槛清单逐项通过。

---

## 2. 状态定义

- `not_ready`
  - 还处于资料收集或方案冻结阶段
- `ready_for_codegen`
  - Flutter 侧抽象和骨架已具备，可开始实现
- `ready_for_platform_validation`
  - 已有可运行实现，可开始真机联调
- `ready_for_release_scope`
  - 已通过首轮交付门槛，可纳入正式版本范围

截至 2026-04-29 的结论：

- 当前状态：`ready_for_codegen`

---

## 3. 必过门槛总表

| 类别 | 门槛 | 必须通过 |
|---|---|---|
| 构建基线 | Flutter runtime / 打包 / 安装 / 启动稳定 | 是 |
| 协议基线 | HTTP / WebSocket / token refresh / WS reauth | 是 |
| 存储基线 | preferences / secure storage 替代路径 | 是 |
| 文件基线 | file picker / image picker / upload / download | 是 |
| 语音基线 | recorder / audio player / pause / resume | 是 |
| 文件打开 | external opener 或可靠降级 | 是 |
| 聊天主链路 | 会话 / 聊天 / 消息菜单 / emoji / 自定义表情 | 是 |
| 高风险增强 | RTC / push / map | 否，首轮可暂缓 |

## 4. M0 构建与运行门槛

### 4.1 必须通过

1. OpenHarmony Flutter runtime 可稳定启动
2. Debug 构建可安装到真机
3. Release 构建链路可跑通
4. 首屏进入登录页无崩溃
5. 热重载或等效开发调试链路可接受

### 4.2 验收证据

- 真机启动录屏
- 首屏日志
- 构建命令与产物说明

### 4.3 不通过判定

出现以下任一情况即不通过：

1. 启动即崩溃
2. 首屏渲染空白
3. Release 包无法稳定安装

---

## 5. M1 协议与登录门槛

### 5.1 必须通过

1. 登录成功
2. refresh token 成功
3. HTTP refresh 成功后可触发同连接 WS reauth
4. 会话列表首次拉取成功
5. WebSocket 可持续收消息

### 5.2 验收证据

- 登录成功录屏
- token 过期后自动恢复录屏
- socket 重连与 reauth 日志

### 5.3 失败即阻塞

以下问题任何一个存在，都不能宣告主链路可交付：

1. refresh 成功但 socket 身份未恢复
2. 会话列表和聊天页需要手动重进才能恢复
3. token 丢失或存储不稳定

---

## 6. M2 P0 原生能力门槛

### 6.1 文件选择

必须通过：

1. 选择普通文件
2. 选择图片
3. 选择视频
4. 拍照入口

绑定文档：

- `IM-FlutterOpenHarmony适配器骨架模板-v1.0.md`

### 6.2 权限

必须通过：

1. 麦克风权限申请
2. 相机权限申请
3. 相册或文件读取权限申请
4. 权限拒绝后可给出正确 UI 反馈

### 6.3 录音

必须通过：

1. 开始录音
2. 取消录音
3. 结束录音并返回音频文件
4. 录音时长和文件大小可读

### 6.4 语音播放

必须通过：

1. 播放语音
2. 暂停
3. 续播
4. 播放完成回调

### 6.5 外部打开

必须通过其一：

1. 文件下载后可外部打开
2. 若系统无可用 app，可正确回退到下载成功提示与失败提示

3. 长按菜单

2. anchor 进入
3. restore 进入
4. 文本发送
5. 图片发送
6. 视频发送
7. 文件发送
8. 语音发送
9. 历史加载
10. 引用定位

### 7.3 消息交互

必须通过：

1. 长按消息菜单
2. 复制
3. 引用
4. 转发
5. 收藏
6. 删除
7. 撤回

### 7.4 媒体交互

必须通过：

1. 图片预览
2. 视频播放
3. 文件打开
4. 文件下载
5. 语音播放暂停续播

## 8. 允许暂缓的能力

OpenHarmony 首轮可以暂缓：

1. 1v1 音视频通话
2. 离线推送
3. 原生地图选点
4. 扫码
5. 系统分享

这些能力可以在文档中存在，但不纳入首轮放行条件。

1. OpenHarmony 已经具备文档层 `ready_for_codegen` 条件

   - 协议层真机联调
