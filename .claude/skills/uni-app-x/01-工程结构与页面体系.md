# 01 工程结构与页面体系

本章覆盖：项目目录结构、pages.json 约定、TabBar、页面跳转规范、静态资源打包规则、条件编译的收敛策略。

## 1.1 现状（仓库对齐）

uni-app x 工程根目录：`shengyu-ui/shengyu-ui-admin-uniappx/`

已存在的关键目录/文件：

- `pages.json`：页面注册与全局样式、tabBar
- `manifest.json`：App 权限与隐私描述等发行配置
- `App.uvue`：应用生命周期、全局初始化（语言、登录检查、WS 前后台）
- `main.uts`：应用入口
- `pages/`：页面（uvue）
- `components/`：组件
- `utils/`：跨业务复用工具（request/websocket/file/nav/storage 等）
- `api/`：后端 API 封装（必须走 `utils/request.uts`）
- `services/`：长生命周期服务（如 read-receipt 等）
- `store/`：状态与缓存（token、locale 等）
- `static/`：静态资源（可被打包到 App）

## 1.2 规范（Principles）

- **页面必须注册**：所有页面必须在 `pages.json` 中注册，否则无法跳转/无法打包。
- **页面只做 UI + 编排**：网络、文件、存储、路由拼接、平台差异必须收敛到 `utils/` / `services/`。
- **跨端差异要收敛**：条件编译尽量写在 utils 层，页面不散落 `#ifdef`。

## 1.3 pages.json（页面注册与全局样式）

### 1.3.1 页面注册

当前 pages 注册包括（节选）：

- IM 主链路：
  - `pages/message/message`
  - `pages/message/chat`
  - `pages/message/chat-files`
  - `pages/common/file-preview`
  - `pages/common/search`

建议约定：

- 页面路径必须与文件路径一致（例如 `pages/common/file-preview.uvue` 对应 `pages/common/file-preview`）。
- 新增“公共能力页面”（例如预览/搜索/选择器）统一放 `pages/common/`。

### 1.3.2 全局样式与导航

从现有 `pages.json` 可见：大部分页面 `navigationStyle: "custom"`。

约束建议：

- 既然采用 custom navigation，页面必须统一使用项目自定义 header（避免不同页面返回/标题行为不一致）。
- `globalStyle` 中如有统一设置（导航栏/背景色等），禁止页面随意覆盖，覆盖必须说明原因。

### 1.3.3 TabBar

当前 `tabBar.iconfontSrc` 指向 `static/iconfont/iconfont.ttf`，tab 图标使用 iconfont。

约束建议：

- iconfont 作为项目级资源，应由专人维护版本；禁止各页面私自引入新的字体文件。

## 1.4 静态资源打包（static 规则）

官方规则要点（已在摘录中记录）：

- App 平台编译时仅会打包 `/static` 下静态资源。
- `web-view` 若加载本地 html，`src` 必须指向 `/static/...`。

对项目建议：

- 所有可离线使用的资源必须放 `static/`；禁止使用其他目录当作静态资源目录。
- 资源路径按“大小写敏感”处理（App 平台存在大小写敏感问题）。

## 1.5 路由跳转规范（项目落点）

### 1.5.1 统一路由工具

- 路由工具：`utils/nav.uts`
- 目前已落地：`navToFilePreview({ fileId, url, name })`

约束建议：

- 新增页面跳转应逐步沉淀到 `utils/nav.uts`，避免页面散落拼接 query。

## 1.6 发行配置与权限（manifest.json）

现状：`manifest.json` 中 App-Android 明确配置了网络/录音/相机/存储/媒体读取等权限；iOS 配置了隐私用途描述。

企业级约束建议：

- 权限遵循“**不用不申**”，避免上架审核风险。
- 任何新增权限必须在 PR 描述中说明：
  - 使用场景
  - 触发时机
  - 用户提示文案
  - 不同 Android 版本的差异处理

## 1.7 Reviewer Checklist

- 禁止项：
  - 新增页面未注册 `pages.json`
  - 页面内散落 `#ifdef`（应优先收敛 utils，除非是 UI 级差异）
  - 页面直接拼接复杂跳转 url（应优先沉淀到 `utils/nav.uts`）
- 必须项：
  - 新增公共能力页面放 `pages/common/`
  - 新增静态资源放 `static/`
  - 新增权限必须说明用途与审核风险

## 1.8 常见问题（Troubleshooting）

- **页面无法跳转**：优先检查 `pages.json` 是否注册、路径是否正确（无 `.uvue` 后缀）。
- **web-view 本地页面无法打开**：检查是否放在 `/static` 下；检查路径大小写。
- **TabBar 图标不显示**：检查 `iconfontSrc` 是否存在、字体文件是否被正确打包。
