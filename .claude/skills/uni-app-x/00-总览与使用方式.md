# 00 总览与使用方式

本手册面向本项目的 uni-app x 端（UTS/uvue），用于沉淀“可执行闭环资料”。

## 目标

- **统一**：工程结构、网络、鉴权、实时、存储、文件、权限、组件、性能、发布等关键能力的实现方式一致。
- **可落地**：每章都包含
  - 规范（Principles）
  - 模板/封装落点（Where & How）
  - Reviewer Checklist（PR 审核项）
  - 常见问题（Troubleshooting）

## 职责原则（本手册存在的唯一理由）

本手册的目标不是整理百科知识，而是**服务本仓库的企业级 IM 项目开发与交付**。

每一条规范/模板/清单都必须能回答：

- 它解决了 IM 的哪一段链路问题（登录态/实时/会话/消息/媒体/文件/权限/性能/发布等）？
- 它对应仓库的哪些落点（`utils/`、`api/`、`services/`、`store/`、`pages/`）？
- 它如何降低踩坑/返工/线上故障概率？

优先级规则：

- 优先沉淀 IM 主链路必需能力（消息收发、WS、鉴权、媒体/文件、长列表性能、权限合规）。
- 与 IM 无关或短期不用的能力，只记录“结论与边界”，不堆大段实现。

## 使用建议

- 需求开发前：先阅读对应章节的 Checklist。
- 代码提交前：按 Checklist 自查，尤其是“禁止项”。
- 线上问题：优先按 Troubleshooting 的日志与定位路径排查。

## 规范来源（权威入口，后续开发默认先自查）

- 本手册（`sql/doc/uni-app-x/*`）：端侧工程落地规范与 Checklist。
- IM 架构设计：`sql/doc/IM即时通讯架构设计文档-v2.0.md`（页面流转、数据契约、不变式）。
- IM 开发任务清单：`sql/doc/IM即时通讯开发任务清单-v2.0.md`（Milestone、依赖、验收口径）。
- 后端 App 端 IM 接口权威来源：
  - `shengyu-module-system/shengyu-module-system-biz/src/main/java/com/shengyu/module/system/controller/app/im`
  - 该目录下 Controller 的 `@RequestMapping/@GetMapping/...` 映射为最终接口口径；端侧 `api/*.uts` 必须对齐。

## 与仓库代码的关系

- 规范优先收敛到 `utils/`、`api/`、`services/`、`store/` 层，页面只负责 UI 与组合调用。
- 典型收敛点：
  - `shengyu-ui/shengyu-ui-admin-uniappx/utils/request.uts`
  - `shengyu-ui/shengyu-ui-admin-uniappx/utils/websocket.uts`
  - `shengyu-ui/shengyu-ui-admin-uniappx/utils/storage.uts`
  - `shengyu-ui/shengyu-ui-admin-uniappx/utils/nav.uts`

## 版本策略

- 本手册记录“当前项目采用的策略”。当 uni-app x 版本升级时，需补充变更点与兼容性验证结论。
