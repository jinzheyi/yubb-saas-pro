# 双端工作台设计与接口契约

## 目标

移除两端首页中的演示项目、虚构访问来源和固定图表。每个工作台只呈现当前登录端可解释、可追溯的真实运营数据，并保留为 AI 助手、异常归因和建议动作预留的位置。

| 端 | 使用者 | 首要问题 | 首页定位 |
| --- | --- | --- | --- |
| platform-vue3 | 平台运营人员 | 租户规模、账号容量、租户健康度、近期变更 | 平台运营驾驶舱 |
| admin-vue3 | 租户管理员 | 团队规模、登录活跃、未读待办、系统公告 | 团队工作台 |

## 信息架构

### 平台运营驾驶舱

1. **运营概览**：租户总数、启用租户、实际租户成员数、平台管理员数。
2. **实时在线**：平台在线人数、租户在线人数；按未过期 OAuth2 access token 的用户编号去重统计。
2. **增长与健康**：近七日新建租户趋势、即将过期租户数、停用租户数。
3. **租户关注队列**：最近创建的租户，显示套餐、账号额度、到期日期和健康状态。
4. **运营动态**：最近公告与平台登录活动。
5. **行动区**：新建租户、租户列表、套餐管理、公告管理；只展示当前账号具备权限的入口。

### 租户团队工作台

1. **欢迎与状态**：当前管理员、当天日期、未读站内信。
2. **团队概览**：团队成员、启用成员、今日登录次数、近七日活跃成员。
3. **活跃趋势**：近七日成功登录次数，空数据也维持完整坐标与解释文案。
4. **待办与公告**：当前用户未读消息、当前租户最新已发布公告。
5. **高频操作**：成员、角色、部门、菜单、公告等内部地址，按现有菜单权限筛选。

## 接口契约

两个接口都使用现有的统一响应包装，首页不再拼接多个表格接口。

| 端 | 接口 | 数据边界 |
| --- | --- | --- |
| 平台端 | GET /system/dashboard/platform-overview | 平台租户、平台账号、平台公告、平台登录日志 |
| 租户端 | GET /system/dashboard/tenant-overview | 当前租户的成员、登录日志、通知消息、公告 |

接口响应统一分为：

- summary：顶部指标和环比/说明信息。
- trend：连续七天的日期和值，前端不生成假趋势。
- recentItems：最近真实记录，限制数量，避免首页全表扫描。
- actions：只包含路由标识和权限标识；前端依据已加载菜单完成跳转。

## 后端实现原则

- 平台端租户用户规模读取 `system_users` 中未删除的实际成员记录，不使用套餐账号额度替代。该跨租户只读聚合严格包裹在 `TenantUtils.executeIgnore` 中；工具方法在 finally 恢复原租户上下文，不会改变后续业务的数据隔离。
- 在线人数来自两个管理端现有的 OAuth2 access token 表：平台端读取 `platform_oauth2_access_token`，租户端读取 `system_oauth2_access_token`。只统计未过期令牌并按用户编号去重；该口径与“访问令牌”管理菜单一致，且不依赖 IM/WebSocket 连接状态。
- 租户端统计基于 TenantBaseDO，由现有租户拦截器自动注入当前租户条件。
- 趋势在服务层按最近七天原始记录聚合，规避特定数据库的日期函数差异。
- 不新增静态样例数据；无记录时返回零值、空列表和连续日期序列。
- 首页接口仅要求登录态，不给普通已登录用户增加额外菜单权限阻碍。

## 视觉与交互

- 平台端使用深浅靛蓝运营横幅、四张指标卡、趋势面板和健康队列，突出规模与风险。
- 租户端使用轻量欢迎区、可点击的指标卡、待办优先级和快捷行动区，突出“今天要处理什么”。
- 数字进入时使用短促计数动画；卡片、列表和图表按 40ms 节奏渐入。
- 响应式顺序为：核心指标 → 待办/风险 → 趋势 → 最近动态；窄屏不牺牲关键动作。
- AI 预留区不虚构智能结论：数据不足时显示“洞察准备中”，有真实指标后再接入建议服务。
