# 管理端设计系统：Astra Console v1

## 目标与边界

本规范同时适用于 `shengyu-ui-admin-vue3` 和 `shengyu-ui-platform-vue3`。目标是在不改变权限、路由、接口与领域逻辑的前提下，建立精致、克制、可扩展的现代管理台体验，并为后续 AI Agent、任务流、知识卡片和流式回答预留一致的界面语言。

本次不引入 Ant Design Vue。继续使用 Element Plus，借鉴 Ant Design 的信息密度、状态反馈与组件秩序；避免双组件库并存造成体积、交互和主题冲突。

## 视觉原则

1. **安静的底，清晰的重点**：大面积中性背景与白色内容承载信息；品牌色仅用于操作、焦点、选中与关键数据。
2. **柔和但不松散**：使用 8px / 12px 圆角、低对比边框和两级柔影，区分层级而不制造厚重卡片墙。
3. **一处一层级**：页面、容器、浮层分别使用不同阴影与边框，不允许同一界面多处竞争性阴影。
4. **动效服务理解**：仅为出现、状态变化、折叠和悬停提供 160–240ms 的过渡；遵从用户的“减少动态效果”系统设置。
5. **AI 原生但不装饰化**：AI 组件通过任务状态、可信来源、流式进度、建议采纳和可回溯操作表达智能性；光晕/渐变只用在 AI 入口与生成态。

## 设计令牌

### 色彩

| 语义 | 浅色值 | 用途 |
| --- | --- | --- |
| 品牌 / `primary` | `#4F46E5` | 主操作、焦点、选中 |
| 品牌悬停 | `#4338CA` | 可交互悬停 |
| AI 辅色 | `#0EA5E9` | Agent、生成与流式状态 |
| 成功 | `#16A34A` | 完成、健康状态 |
| 警告 | `#D97706` | 等待、风险提醒 |
| 危险 | `#DC2626` | 删除、失败 |
| 页面背景 | `#F6F7FB` | 应用画布 |
| 表面 / `surface` | `#FFFFFF` | 卡片、表单、浮层 |
| 标题 / 正文 / 次要 | `#172033` / `#475569` / `#94A3B8` | 信息层级 |

深色模式不通过反相生成，使用深灰蓝画布和略亮的浮层表面；品牌色提升亮度以满足可读性。

### 几何与层级

| 令牌 | 值 |
| --- | --- |
| 紧凑 / 常规 / 强调圆角 | `6px` / `10px` / `14px` |
| 页面间距 | `24px`（窄屏 `16px`） |
| 卡片内边距 | `20px`（复杂信息卡 `24px`） |
| 常规阴影 | `0 1px 2px rgba(15,23,42,.03), 0 8px 24px rgba(15,23,42,.05)` |
| 浮层阴影 | `0 20px 48px rgba(15,23,42,.14)` |
| 常规动效 | `200ms cubic-bezier(.2,.8,.2,1)` |

## 页面骨架

```
应用画布
├─ 导航侧栏：产品标识、分组菜单、低饱和选中底
├─ 顶部栏：定位/面包屑、全局搜索、通知、账户
└─ 内容区
   ├─ 页面标题与上下文操作
   ├─ 筛选区（可折叠，避免单独厚重卡片）
   ├─ 数据区（表格或信息卡）
   └─ 详情/AI 辅助浮层
```

默认使用经典左侧布局。布局切换仍可保留在设置中，但新视觉以此作为完整验收基准。

## 组件规范

### 列表操作

- 表格行内的“修改、详情、新增、删除”等操作使用轻量文字按钮，不使用实心渐变、投影或胶囊形态。
- 主操作使用主色文字，危险操作使用克制的红色文字；悬停时仅提供低饱和背景提示。
- 工具栏中的主操作仍可使用实心按钮，以保持“页面级动作”与“行级动作”的层级区分。

### 导航

- 左侧可展开菜单的箭头固定在标题右侧安全区域，并与标题使用同一垂直中心线，文字始终保留独立的可读空间。
- 标准标签页使用轻量圆角胶囊：非当前页保持低对比，当前页使用主色渐变与克制阴影；前进、后退、刷新等工具入口采用与页签相同中心线的圆角图标按钮。

### 反馈与详情

- 业务页签使用细线、主色短下划线和柔和切换，不使用厚重卡片边框。
- 状态标签保持紧凑圆角与中等字重；提示条、空状态和浮层沿用同一边框、圆角和文本层级。

- **按钮**：主按钮使用品牌实色；次级按钮描边；危险操作保持描边或文字形式，确认页才使用实色危险按钮。
- **输入与选择**：白底、细边框、2px 低透明焦点环；禁止长时间高饱和边框。
- **卡片**：只有业务区块、统计、详情、浮层使用卡片；搜索表单应融入轻量容器，避免嵌套卡片。
- **表格**：浅灰表头、仅横向分隔线、行悬停轻染色；操作列优先使用文字按钮，避免一列堆满实色按钮。
- **弹窗与抽屉**：浮层圆角 14px、顶部/正文/底部信息分区清楚；抽屉用于连续上下文，弹窗用于短任务确认。
- **空、加载、错误状态**：必须解释下一步操作；AI 生成状态还须显示阶段、停止按钮和来源/结果边界。

## AI Agent 预留模式

1. `AgentEntry`：顶部或页面动作区的克制入口，不与主提交按钮竞争。
2. `AgentPanel`：右侧抽屉优先，包含会话、步骤、引用、结果和人工确认区。
3. `AgentStatus`：`idle / thinking / streaming / needs-review / complete / failed` 六态，颜色不是唯一信号，配合图标与文案。
4. `AgentArtifact`：生成的表格、草稿、流程或建议须有版本、来源和“应用/撤销”操作，不直接静默写入业务数据。

## 动效规范

- 页面切换：向上位移 `8px` 并淡入，`180ms`；离场仅淡出 `120ms`，不阻塞导航。
- 内容容器：首次进入使用 `6px` 位移与轻微缩放，最多三级、每级延迟 `35ms`，使筛选区和数据区自然建立阅读顺序。
- 可操作元素：按钮悬停仅提升阴影，按下缩放到 `0.98`；表格行只改变轻量背景，禁止整行跳动。
- 弹窗、下拉、通知：使用统一浮层阴影和圆角，由组件自带出现/离场过渡承载，不叠加夸张动画。
- 无障碍：`prefers-reduced-motion` 下全部过渡与动画缩短至近乎即时；动画不是理解状态的唯一方式。

## 实施顺序与验收

1. 建立统一令牌与 Element Plus 适配层，清理旧主题覆盖冲突。
2. 重构壳层、导航、顶栏、页签与内容画布。
3. 重构查询、表格、表单、弹窗、统计卡和空状态等页面原语。
4. 以登录、首页、标准列表页作为双端视觉回归样板，再按业务域推广。
5. 最后清理废弃商城、会员、支付域及其关联装修器资源，并进行构建与路由审计。

验收标准：两个端在相同原语上保持同一视觉；浅/深色和窄屏无明显回退；键盘焦点可见；`prefers-reduced-motion` 生效；无业务接口、权限或动态菜单回归。
