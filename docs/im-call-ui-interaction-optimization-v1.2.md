# 音视频通话交互优化设计（微信式最小体验）v1.2 终审版

> 文档状态：可进入 UI 实施与验收  
> 编写日期：2026-08-28  
> 适用端：Flutter Android / iOS / Web  
> 适用范围：单聊语音、单聊视频、群聊语音、群聊视频  
> 核心约束：只优化现有能力的界面与交互，不新增业务功能，不更换 LiveKit，不破坏服务端通话协议；仅允许向后兼容的可选展示字段

### v1.2 终审说明

本版是在逐项复核聊天入口、群成员选择、通话路由、WebSocket 来电绑定、原生来电页、Flutter controller、LiveKit 房间、铃声、服务端接口、群成员状态和终态事件后形成的施工版，重点补齐：

- 单聊语音 / 视频从入口到结束的逐状态详细 UI 图；
- 群成员选择、群语音、群视频从邀请到成员离开的详细 UI 图；
- 1 人、2 人、3～4 人、5～9 人群视频布局；
- 主叫 / 被叫、群主叫 / 群受邀成员的不同按钮语义；
- 前台来电、后台原生来电、原生接听、恢复通话、弱网、终态的页面状态；
- 展示字段从哪里取得、缺失时如何降级；
- Flutter、Android、iOS、服务端和测试文件的逐文件改动要求。

本版仍然不要求增加新的通话动作。为展示群名、头像等已有业务资料，可以增加向后兼容的可选展示字段，或优先复用本地会话 / 群成员缓存；不得因此改变通话状态机和接口业务语义。

终审新增确认：

- 除聊天页外，`ContactProfilePage` 也是单聊通话入口，必须与聊天页共用同一通话方式弹层、活动通话拦截和展示参数。
- 群角色不能再由 `entryMode == outgoing` 推断；owner 从 `/active` 恢复后 `entryMode` 为 `restore`，现有 controller 会错误选择 `/group/leave`。必须显式携带并派生 `isGroupOwner`。
- 当前 `OfflinePushServiceImpl.pushCallInvite()` 返回 `NOT_CONFIGURED`。因此本项目只能保证 App 在线或进程仍能收到 WebSocket 时的系统来电，不能把“App 被杀后的离线锁屏来电”列为本轮已实现能力。
- 服务端默认 240 分钟会以 `MAX_DURATION` 终止通话，UI 必须提供用户文案映射。

## 1. 结论先行

本轮不应继续扩展通话能力，而应把现有能力重新组织成一套清晰、稳定、接近微信基本通话习惯的状态化界面：

1. 来电时先识别人和通话类型，再决定拒绝或接听。
2. 等待接听时突出对方、呼叫状态和“取消”，不让设备按钮抢夺注意力。
3. 接通后以通话内容为主：语音以头像和计时为主，视频以远端画面为主。
4. 所有控制按钮必须同时具备图标、中文标签和开关状态，不再依赖用户猜图标。
5. 弱网和失败使用短句提示，不直接向用户显示 LiveKit 异常、堆栈或内部服务名。
6. 单聊与群聊复用一套视觉语言，但群视频使用成员网格，单聊视频使用“远端全屏 + 本地小窗”。
7. 本轮明确不做悬浮窗、屏幕锁定、忽略来电、邀请新成员、录制、美颜、背景虚化、屏幕共享、通话内聊天、通话类型切换等扩展能力。

最终目标不是逐像素复制微信，而是借鉴其成熟的信息层级、按钮语义和状态反馈，同时保留本项目现有调用链。

## 2. 现有实现审计

### 2.1 当前能力边界

现有代码已经具备下列能力，UI 优化应直接复用，不增加新的业务接口：

| 能力 | 现有入口 / 状态 | 本轮处理 |
|---|---|---|
| 单聊语音、视频发起 | `chat_page.dart` 创建 `CallLaunchArgs.outgoing` | 保留 |
| 群聊成员选择后发起 | `group_call_member_select_page.dart` | 保留 |
| 来电接听、拒绝 | `acceptIncoming()` / `rejectIncoming()` | 只优化按钮与反馈 |
| 主动挂断、群成员离开 | `hangup()` | 保留服务端语义 |
| 麦克风开关 | `toggleMicrophone()` | 优化标签和选中态 |
| 扬声器开关 | `toggleSpeaker()` | 移动端展示；Web 按真实可用性处理 |
| 摄像头开关 | `toggleCamera()` | 视频通话展示 |
| 前后摄像头切换 | `switchCamera()` | 摄像头开启时可用 |
| 本地、远端视频渲染 | LiveKit track renderer | 重排画面布局 |
| 来电铃声、结束音 | `CallAudioCueService` | 不改变音频职责 |
| 系统来电页衔接 | `NativeCallUiGateway` | 保持现有行为 |
| 重连和 15 秒超时 | `reconnecting` / controller timer | 改为非技术化提示 |

### 2.2 当前 UI 的主要问题

当前 `livekit_call_page.dart` 是完整黑底的纵向 `Column`，顶部固定标题和状态，中间渲染媒体，底部将全部操作按钮排列在同一行。它能完成操作，但存在以下体验问题：

| 问题 | 当前表现 | 用户影响 |
|---|---|---|
| 联系人识别弱 | 语音页只显示 128px 通用人形图标 | 来电和通话对象缺少真实感，群聊与单聊也难区分 |
| 按钮无文字 | 来电和通话按钮只有 Material 图标 | 用户需要猜测“听筒、扬声器、翻转”等含义 |
| 状态层级混乱 | `title`、状态、错误文本都在主纵向流 | 关键操作与次要状态争夺注意力 |
| 技术错误外露 | 直接红字展示 `_controller.error` | 会出现 LiveKit、网络异常对象等技术信息，不适合终端用户 |
| 来电反馈不准确 | 接听过程中仍可能显示“来电中”，两端按钮同时变沙漏 | 不清楚是否已点击成功，也不清楚正在执行哪个动作 |
| 单聊视频缺少主次 | 远端使用 `GridView`，本地固定 110×160 | 1v1 场景没有明确的“对方为主、自己为辅”模型 |
| 群视频模型不完整 | 远端进网格、本地永远以小窗出现 | 群聊中自己的身份与其他成员层级不一致 |
| 控件过密 | 视频通话最多五个圆按钮挤在同一行 | 小屏设备容易误触，标签也没有空间 |
| 控件状态不显著 | 开/关主要通过图标变化表达，背景都为蓝灰 | 视力较弱或不熟悉图标的用户难以确认设备状态 |
| Web 行为含混 | Web 上扬声器按钮仅改变布尔值，未实际路由音频输出 | UI 看起来成功，实际没有效果 |

### 2.3 可直接复用的现有组件与数据

- `AppAvatar` 已支持网络头像、缓存、失败回退和首字头像，应替换通话页的 `Icons.person`。
- `GroupAvatarWidget` 已存在，可在能够取得现有群成员头像时复用；拿不到时使用群名首字回退，不新增接口。
- `CallLaunchArgs.title` 已能从聊天页和来电 `callerProfile.displayName` 传入。
- 单聊来电 payload 已明确包含 `callerProfile.displayName` 与 `callerProfile.avatarUrl`；群来电 payload 已包含 `callerName` 与 `callerAvatar`；`/active` 恢复接口也已返回 `callerName` 与 `callerAvatar`。这些字段当前只是没有完整传入 `CallLaunchArgs`。
- `room.remoteParticipants`、本地与远端 track、`elapsedSeconds` 已足够完成视频布局、接通人数和计时展示。

### 2.4 全链路现状与 UI 数据边界

```text
聊天页通话菜单
  ├─ 单聊：直接创建 CallLaunchArgs.outgoing
  └─ 群聊：成员选择（最多 8 名受邀者）→ CallLaunchArgs.outgoing
           │
           ▼
LiveKitCallPage → LiveKitCallController
  ├─ HTTP create / accept / connection / reject / hangup / group-leave
  ├─ LiveKit Room：真实媒体、参与者、音视频 track
  └─ CallAudioCueService：前台铃声、结束音
           ▲
           │
SYSTEM_NOTIFY ← CallEventPublisher / outbox ← 服务端通话状态机
  ├─ call.invite / call.group_invite
  ├─ call.accepted / call.group_join / call.group_leave
  └─ call.rejected / call.cancelled / call.ended / call.timeout / call.group_ended
           │
           ├─ App 前台：直接打开 Flutter 通话页
           └─ App 后台：NativeCallUiGateway → Android 全屏来电 / iOS CallKit
```

#### 2.4.1 已有展示字段

| 场景 | 已有来源 | 当前是否传到通话页 | v1.2 要求 |
|---|---|---:|---|

| 单聊去电头像 | 当前会话对象 / 页面已有会话资料 | 否 | 作为可选展示字段传入，不请求新接口 |
| 单聊来电昵称 | `callerProfile.displayName` | 是，转为 `args.title` | 拆为明确的 `callerName` 更佳 |
| 单聊来电头像 | `callerProfile.avatarUrl` | 否 | 在 binding 中解析并传入 |
| 群去电群名 | `GroupCallMemberSelectArgs.groupName` / `chatTitle` | 是，最终在 `args.title` | 明确保存为 `conversationTitle` |
| 群来电主叫昵称 | `callerName` | 是，当前被当作 `title` | 作为主叫身份显示 |
| 群来电主叫头像 | `callerAvatar` | 否 | 在 binding 中解析并传入 |
| 群来电群名 | payload 当前没有；本地会话缓存可按 `chatId` 取得 | 否 | 先读本地缓存；没有则显示“群语音/视频通话”，不得阻塞来电页 |
| 恢复通话主叫资料 | `/system/im/call/active` 的 `callerName/callerAvatar` | 昵称有、头像未传 | 全部传入 |
| 群成员名称 / 头像 | `groupMembersFutureProvider(groupId)` 与已有群成员缓存 | 通话页未使用 | 非阻塞加载，track identity 按 userId 映射；失败显示稳定首字占位 |
| 本地成员名称 / 头像 | `currentUserProfileProvider` + `authSessionProvider.userId` | 通话页未使用 | 群网格“我”格位非阻塞读取；资料未到时显示“我”的稳定占位 |

#### 2.4.2 不可错误推断的数据

- `controller.connected` 只表示本机已经连入 LiveKit，不等于对方已接听。
- 单聊“已接通”必须以 `hasRemoteParticipant` 或已确认的远端 participant 为准。
- 群通话服务端变为 `CONNECTED` 后，仍可能只有发起者一人在房间；UI 应显示“等待成员加入…”。
- `call.group_join` 只表明某个群成员接受邀请，不代表所有受邀人都已加入。
- LiveKit webhook 当前只校验并记录媒体事实，不裁决 UI 状态，Flutter 页面不得等待 webhook 更新。
- `call.group_leave` 不是整场终态；只移除对应成员。`call.group_ended` 才关闭所有群通话页面。
- `reason` 当前可能是 `REJECT`、`CANCEL`、`HANGUP` 等内部枚举，不能直接显示。

#### 2.4.3 复核发现的核心交互约束

1. `LiveKitCallPage` 对用户主动退出始终调用 `controller.hangup()`；直聊未接通时服务端会按取消收敛，接通后按挂断收敛。因此 UI 可根据展示阶段写“取消 / 挂断”，不能仅凭按钮文案自行改 endpoint。
2. 群发起者是 owner：当前 outgoing 群通话调用 `/hangup`，会结束整场；群受邀成员调用 `/group/leave`，只离开自己。因此二者按钮文案必须分别为“结束通话”和“退出通话”。
3. 原生系统接听通过 `acceptedFromNative` 进入页面，当前代码直接把 `_accepted` 设为 true，但未把 `_accepting` 设为 true；新版视觉状态必须把“原生已接听但媒体尚未连接”识别为 `accepting`，不能提前展示可点击设备控制。
4. `restore` 入口当前在连接完成前也会落入普通操作区；新版必须有独立 `restoring` 状态。
5. 设备按钮在本地 participant 尚未准备好时点击不会生效；必须禁用到 `room.localParticipant != null`，不能提供虚假反馈。
6. 群成员选择上限实际是 8 名受邀者，加发起者共最多 9 人。当前第 9 次选择会静默失败；新版必须明确提示“最多选择 8 位成员”。
7. 当前终态收到后页面在下一帧直接关闭，结束原因几乎不可见。新版应立即释放媒体和停止铃声，但允许 600～900ms 的纯展示结束层后再退出；这不是等待服务端。
8. 联系人资料页已有 `_callLaunchInProgress + liveKitCallActivityProvider.isActive` 双重拦截，但仍重复实现弹层、未透传联系人头像且直接显示 `error.toString()`；必须与聊天页统一展示组件和错误映射。
9. 群 owner 从 `/active` 恢复后属于 `entryMode.restore`。现有 `hangup()` 以“是否 outgoing”决定 `/hangup` 或 `/group/leave`，会丢失 owner 语义；必须改为以显式群角色判断。

### 2.5 全链路实现前置修正（不新增功能）

下列事项不是 UI 扩展，而是现有群通话与展示一致性的必要修正，应与 UI 实施一起确认：

- 群成员拒绝邀请应依据该成员自己的 `inviteState` 判断，不能因为其他成员先接听、全局通话已为 `CONNECTED` 就拒绝执行；否则后接到页面的成员点击“拒绝”会报状态错误。
- outbox 判断群邀请是否过期时应核对对应 participant 的邀请状态，而不能只看全局 call 是否仍为 `RINGING`；否则首位成员接听后，尚未投递的其他群邀请可能被跳过。
- `LiveKitCallEvent` 应解析 payload 已有的 `actorId`，用于区分本人和对方触发的终态；这只是进程内 DTO 补全，不改 WebSocket 协议。群成员姓名提示仍不要求，因此 `group_join/group_leave.userId` 可不进入展示层。
- `AppCallLiveKitWebhookController` 继续只做验签与日志，不新增 UI 反向驱动逻辑。
- 群 owner 角色必须在 outgoing、native encode/decode 和 `/active` 恢复三条路径保持一致；controller 的 hangup 与媒体失败补偿都不能再把 `entryMode` 当角色。
- 当前未配置 APNs/FCM/厂商离线来电推送，UI 文档只验收在线 / 进程存活场景的系统来电。终止进程来电属于既有离线推送部署文档范围，不借 UI 改造扩充。

## 3. 微信界面调研与取舍

### 3.1 可借鉴的稳定模式

公开的微信语音通话界面样例持续呈现出一组稳定模式：深色沉浸背景、显著的联系人头像与昵称、短状态文案、底部大尺寸圆形操作按钮，以及“拒绝/接听”“静音/挂断/扬声器”等直接中文标签。接通后，状态区域改为计时，而不继续显示技术连接过程。相关界面可参见[微信语音来电与扬声器操作示例](https://jingyan.baidu.com/article/17bd8e523da791c4aa2bb86f.html)和[微信语音接通计时界面示例](https://jingyan.baidu.com/article/3a2f7c2e72634e67aed6110a.html)。

公开的视频通话样例则以远端视频作为最大视觉区域、本地视频作为角落小窗，设备控制覆盖在底部；麦克风、扬声器、摄像头均通过“已开/已关”文字协助用户判断状态。可参见[微信视频通话设备控制界面示例](https://jingyan.baidu.com/article/c74d6000d531f74e6b595d0f.html)。

腾讯官方通话 UI 指南也将界面拆分为“通话画面 + 状态驱动控制”，明确建议监听设备状态实时刷新按钮，并让接听、挂断、拒接按钮随通话阶段变化；官方示例采用约 60dp 的圆形挂断与设备按钮。2026 年仍在更新的 `CallCoreView` 文档进一步确认了单人 / 多人布局、按 userId 配置头像、等待界面和网络状态提示这些基础模型。参见[腾讯云通话界面实现指南](https://cloud.tencent.com/document/product/647/130650)和[CallCoreView 文档](https://intl.cloud.tencent.com/zh/document/product/647/81727)。

因此，本项目采用的是以下“模式借鉴”，而不是微信资产复制：

- 深色、低干扰背景；
- 头像 / 昵称 / 状态的清晰纵向层级；
- 红色表示拒绝或结束，绿色只表示接听；
- 每个图标下方放置短标签；
- 接通计时从真正出现远端参与者后开始；
- 视频远端主画面、本地小窗；
- 设备按钮状态与真实媒体状态同步。

### 3.2 当前微信新增能力为何不跟进

2026 年公开报道中的微信视频通话已经加入屏幕锁定，锁定后隐藏挂断、扬声器、麦克风、摄像头等控件以减少误触；这说明防误触是成熟产品的重要方向，参见[腾讯新闻相关说明](https://news.qq.com/rain/a/20260327A05CZO00)。但它需要新的锁定状态、解锁手势和可发现性设计，不属于本项目现有核心能力，所以本轮不实现。

微信近期公开测试的“忽略来电”也会改变来电生命周期与对端感知，不是单纯的 UI 换肤，参见[来电“忽略”交互说明](https://www.woshipm.com/share/6304388.html)。本项目当前只有接听和拒绝语义，本轮不得用“静音”“最小化”等视觉按钮伪装成忽略能力。

### 3.3 研究使用边界

- 公开截图来自不同微信版本和不同系统，只用于识别长期稳定的信息层级，不作为像素级还原依据。
- 不复制微信图标、音效、商标、字体或专有素材。
- 最终尺寸以本项目 Flutter 布局、真机安全区和可用性测试为准。
- Android 官方建议交互目标至少为 48×48dp，目标之间保留约 8dp 间距；本方案的主操作按钮按 64dp 设计，满足这一基线。参见[Android 触摸目标尺寸指南](https://support.google.com/accessibility/android/answer/7101858?hl=zh-Hans)。

## 4. 设计原则

### 4.1 一屏只回答三个问题

任何通话阶段都必须让用户在一眼内知道：

1. 正在与谁或哪个群通话？
2. 当前是什么状态？
3. 现在最主要的操作是什么？

不满足这三个问题的信息不进入第一视觉层级。

### 4.2 状态先于装饰

页面不是根据“音频页 / 视频页”写两套零散条件，而是先派生唯一的展示阶段，再由阶段决定标题、状态、画面和按钮。建议 UI 层使用以下展示枚举，不改变服务端状态机：

```dart
enum CallVisualPhase {
  incoming,
  accepting,
  dialing,
  waitingRemote,
  restoring,
  connected,
  reconnecting,
  ending,
  failed,
}
```

### 4.3 只显示真实可用的操作

- 来电未接听：只显示拒绝、接听。
- 接听提交中：拒绝和接听都禁用，只在接听按钮中显示进度。
- 语音等待 / 已接通：显示麦克风、挂断、扬声器。
- 视频等待 / 已接通：显示麦克风、挂断、摄像头、翻转。
- 摄像头关闭时：翻转按钮禁用并降低透明度。
- Web 无法真正切换扬声器输出时：不显示扬声器按钮，不能只修改本地布尔值制造成功假象。
- 正在结束：所有操作禁用，避免重复请求。

### 4.4 文案面向用户，不面向开发者

禁止在界面显示：`LiveKit`、`PeerConnection`、URL、token、HTTP 状态、异常类名和完整 `error.toString()`。技术详情只写入日志。

## 5. 视觉系统

### 5.1 色彩

| 角色 | 建议值 | 用途 |
|---|---|---|
| 页面底色 | `#0B0B0D` | 语音页及无视频占位 |
| 视频遮罩 | 黑色 20%～55% 渐变 | 保证顶部状态和底部控件可读 |
| 主文字 | `#FFFFFF` | 昵称、计时、按钮标签 |
| 次文字 | `#FFFFFFB3` | 呼叫状态、说明 |
| 控件默认底色 | `#FFFFFF24` | 开启中的设备控制 |
| 控件关闭底色 | `#F2F2F2` | 关闭中的设备控制 |
| 控件关闭图标 | `#202124` | 与浅色底形成清晰对比 |
| 挂断 / 拒绝 | `#FA5151` | 破坏性动作 |
| 接听 | `#07C160` | 仅来电接听动作 |
| 弱网提示 | `#FFB020` | 非阻断状态条 |

绿色只用于“接听”，避免把普通开关也做成绿色，保持动作语义稳定。

### 5.2 字体层级

| 内容 | 字号 | 字重 | 行数 |
|---|---:|---|---:|
| 单聊昵称 / 群名 | 22sp | 600 | 1，超长省略 |
| 接通计时 | 17sp，等宽数字优先 | 500 | 1 |
| 呼叫状态 | 15sp | 400 | 1 |
| 控件标签 | 13sp | 400 | 1 |
| 弱网 / 失败提示 | 14sp | 400 | 最多 2 |

### 5.3 尺寸与安全区

- 主操作圆形按钮：64×64dp；图标 28dp。
- 普通设备圆形按钮：56×56dp；图标 26dp；完整点击区不小于 56dp。
- 按钮标签距离圆形按钮 8dp。
- 按钮组水平间距不小于 20dp；小屏时使用 `Wrap` 或等宽四列，不压缩点击区。
- 底部控制区距系统安全区 20dp，距可视底部建议 28～36dp。
- 页面左右安全边距 24dp。
- 本地视频小窗：宽度为屏宽 27%～30%，推荐 108×152dp；距离右侧 16dp、顶部安全区下方 16dp；圆角 12dp，1dp 半透明描边。
- 以 360×800dp 为最低手机基准完成无溢出验证，再验证 390×844dp 和横屏 / Web 窄窗口。

### 5.4 响应式断点

| 宽度 | 页面策略 | 控制区策略 |
|---:|---|---|
| `< 360dp` | 极窄屏；头像缩至 80dp，左右边距 16dp | 标签保持，按钮不小于 52dp；必要时两行 |
| `360～599dp` | 标准手机施工图 | 按本文 56/64dp 执行 |
| `600～899dp` | 平板 / Web 窄窗；内容居中 | 语音内容最大宽 520dp；控制区最大宽 480dp |
| `≥ 900dp` | Web / 桌面；黑色全窗舞台 | 单聊视频舞台最大 16:9 或 4:3 区域居中；群网格最大宽 1200dp |

- Web 不能简单把手机页面拉满到浏览器全宽，语音头像和按钮必须保持可读尺度。
- Web 鼠标 hover 只增加 8% 亮度，不能改变开关状态色。
- Web 为接听、拒绝、挂断、麦克风、摄像头提供 tooltip 和键盘焦点；`Enter/Space` 触发聚焦按钮，`Esc` 视为返回并进入现有终结流程。
- 横屏手机的视频控制区放在右侧或底部均可，但必须保留红色按钮与其他按钮的视觉距离；首版若不支持横屏，应锁定方向而不是让布局溢出。

### 5.5 层级与遮罩

视频页面固定分为三层：

```text
底层：远端视频 / 群视频网格
中层：顶部与底部黑色透明渐变、无视频头像占位
顶层：身份状态、弱网条、本地小窗、控制按钮、结束层
```

- 顶部渐变高度建议 160dp：顶端黑色 55% → 末端透明。
- 底部渐变高度建议 240～280dp：底端黑色 72% → 顶端透明。
- 控制按钮不能直接压在高亮视频区域而没有遮罩。
- 弱网条的 z-index 高于视频与身份栏，低于系统权限弹窗和结束层。
- 结束层覆盖所有内容并拦截点击。

## 6. 状态与现有代码的唯一映射

| `CallVisualPhase` | 现有条件 | 主文案 | 页面主操作 |
|---|---|---|---|
| `incoming` | `entryMode == incoming && !_accepted && !_accepting` | “邀请你语音通话” / “邀请你视频通话” | 拒绝、接听 |
| `accepting` | `_accepting == true` | “正在接通…” | 两键禁用，接听键进度 |
| `dialing` | outgoing 且 controller 尚未 connected | “正在呼叫…” | 取消；设备控制按可用性展示 |
| `waitingRemote` | `connected && !hasRemoteParticipant` | “等待对方接听…” | 取消；设备控制 |
| `restoring` | `entryMode == restore && !connected && !shouldClose`，或原生接听后的恢复窗口 | “正在恢复通话…” | 仅允许退出，设备控制禁用 |
| `connected` | `connected && hasRemoteParticipant && !reconnecting` | `mm:ss` / 超过一小时 `hh:mm:ss` | 通话控制 |
| `reconnecting` | `reconnecting == true` | “网络不稳定，正在恢复…” | 保留挂断，其余禁用或保持原态 |
| `ending` | `_closing == true` 或已触发终结 | “通话已结束” | 全部禁用，短暂淡出 |
| `failed` | 有面向用户的失败且页面尚未关闭 | 失败短句 | 无操作或仅挂断，随后按现有生命周期关闭 |

优先级必须固定为：`ending/failed > reconnecting > accepting > incoming > restoring > connected > waitingRemote > dialing`，避免多个布尔值同时为真时界面跳错状态。

- remote participant 存在但 video track 尚未订阅时显示“视频连接中…”，不能误写“对方摄像头已关闭”；需要根据 publication 是否存在及 mute / subscribed 状态区分。
- 首版控制常驻，不做点按画面隐藏，也不做拖动小窗或主辅画面交换。

### 7.10 群语音来电

群来电当前稳定具备主叫昵称 / 头像，但群名可能只存在本地会话缓存，因此采用双层身份：能取群名则显示群名，取不到也能正常接听。

```text
有群名                                    无群名降级
┌────────────────────┐                  ┌────────────────────┐
│      [群头像]       │                  │     [主叫头像]      │
│       项目群         │                  │        张三         │
│ 张三邀请你加入群语音  │                  │ 邀请你加入群语音通话 │

│   ●            ◎   │                  │   ●            ◎   │
│  拒绝          接听  │                  │  拒绝          接听  │
└────────────────────┘                  └────────────────────┘
```

- 群名取得优先级：`args.conversationTitle` → 本地 conversation cache by `chatId` → “群语音通话”。
- 主叫头像取得优先级：`callerAvatar` → `AppAvatar(callerName)`。
- 拒绝只拒绝当前成员邀请，不应结束其他成员的群通话。

### 7.16 通话结束层

```text
┌──────────────────────────────────┐
│                                  │
│                                  │
│             通话已结束             │  17sp / 600
│             03:28                │  有时长才显示
│                                  │
│                                  │
│                                  │
└──────────────────────────────────┘
```

文案按终态映射：

- 本人取消：`已取消`；
- 本人挂断 / 退出：`通话已结束`；
- 对方拒绝：`对方已拒绝`；
- 对方取消：`对方已取消`；
- 对方挂断：`对方已挂断`；
- 超时：`对方无应答`；
- 其他设备接听：`通话已在其他设备接听`；
- 网络失败：`网络连接中断，通话已结束`；
- 群主结束：`群通话已结束`。

实现时先同步停止铃声、释放 camera / microphone / Room，再保留 600～900ms 纯展示层后 `Navigator.pop()`；用户主动挂断可以缩短至 400～600ms。结束音仍由现有服务去重播放一次。

### 7.17 后台与锁屏系统来电

后台和锁屏界面由 Android 全屏来电 / iOS CallKit 控制，不应尝试用 Flutter 页面覆盖系统 UI。当前成立前提是 App 进程仍存活且 WebSocket 事件能够到达；`OfflinePushServiceImpl` 尚未配置真实离线来电推送，所以 App 被系统杀死后的来电不属于本轮可验收能力。进程存活场景必须保证信息和动作语义一致：

```text
┌──────────────────────────────────┐
│             圣钰 IM               │
│                                  │
│             [系统头像*]            │
│              对方昵称              │
│         圣钰 IM 语音/视频通话        │
│                                  │
│       拒绝                接听      │
└──────────────────────────────────┘
```

`*` 系统插件不能稳定展示头像时允许只显示名称，不阻塞来电。

- Android 使用现有 `textDecline=拒绝`、`textAccept=接听`，应用名和通话类型可读。
- iOS 使用系统标准 CallKit 交互，不自定义仿微信按钮。
- 系统点击接听：停止系统铃声 → 打开 Flutter 接听中页 → REST accept → LiveKit connect → `setConnected()` → 正常通话页。
- 系统点击拒绝：调用 `/reject`、播放一次结束音、清理 native call；不再打开 Flutter 页。
- 系统超时：清理 native call，并由服务端 / 生命周期任务收敛未接状态。
- App 回前台时 `_reconcileActiveCall()` 只恢复仍为 ringing / connecting / connected 的真实通话，不能把已结束来电重新弹出。
- 不得在 UI 验收报告中把“后台收到 WebSocket 后拉起系统页”表述成“离线推送已完成”。
- 将来单独部署离线推送时，还需把单聊嵌套的 `callerProfile` 展平为 push data 的 `callerName/callerAvatar`；当前 `CallPushService.pushData()` 只复制顶层字段。这是未来离线链路兼容项，不纳入本轮 UI 实现。

### 7.18 权限与浏览器媒体授权

#### 移动端首次权限

- 单聊 / 群聊语音：只请求麦克风。
- 单聊 / 群聊视频：请求麦克风和摄像头。
- 去电在创建服务端邀请前请求，避免对方收到一个本机无法建立媒体的邀请。
- 来电在用户点击接听后请求，避免未同意通话就弹媒体权限。
- 临时拒绝：显示“需要麦克风权限才能通话”或“需要摄像头和麦克风权限才能视频通话”，随后结束本次通话。
- 永久拒绝：本轮不新增复杂设置引导页；可在短提示中提供现有通用“去设置”能力（如果项目已有），没有则只结束并返回。

#### Web 浏览器授权

```text
┌──────────────────────────────────┐
│             [头像]                │
│              对方昵称              │
│      请允许浏览器使用麦克风和摄像头   │
│                                  │
│              正在等待授权…          │
│                                  │
│                ●                 │
│               取消                │
└──────────────────────────────────┘
```

- Web 权限由 `getUserMedia` / LiveKit SDK 在用户动作中触发，Flutter 页面显示等待授权但不伪造自定义权限弹窗。
- 浏览器拒绝后映射为用户文案，不展示 `NotAllowedError`、`MediaDeviceFailure` 等异常名。
- 浏览器来电铃声可能受自动播放策略限制，页面视觉来电态必须足够明确；本轮不增加绕过浏览器策略的实现。
- Web 无真实 speaker routing 控制时不显示扬声器按钮。

### 7.19 通话结束后的聊天记录

通话页退出不是体验终点。现有聊天时间线已经支持单聊通话记录气泡和群聊居中记录，应保留，但统一为准确、可扫读且不可误触的最小样式；本轮不增加点击回拨。

#### 单聊记录

```text
对方消息：                         本人消息：
┌────────────────────┐            ┌────────────────────┐
│ ☎  对方已取消       │            │ 视频通话时长 03:26  🎥 │
└────────────────────┘            └────────────────────┘

未接来电：☎ 未接听
本人取消：☎ 已取消
对方拒绝：☎ 对方已拒绝
忙线：    ☎ 对方正在通话中
已接通：  ☎ 语音通话时长 03:26
```

- 沿用普通聊天气泡左右归属和主题颜色；图标只标识语音 / 视频，不附加新动作。
- 文案必须结合 `isOutgoing` 与状态确定主体，不能把收到的“拒绝”写成自己已取消。
- 时长沿用 `MM:SS`，超过一小时用 `HH:MM:SS`。

#### 群聊记录

```text
               ── 雷军发起了群视频通话 ──
               ── 群视频通话已结束 12:08 ──
```

- 继续使用时间线居中、12sp 次要文字，不占用成员消息气泡。
- 当前 `_CallRecordCenteredMessage` 在群未接 / 拒绝 / 取消时可能生成“邀请你和…加入了群聊”，这与通话语义不符，必须改为“某某发起了群语音/视频通话”或服务端状态允许时显示“群语音/视频通话已取消”。
- 群结束记录只展示群通话事实和时长，不展开受邀成员名单，不新增详情入口。
- 记录到达晚于通话页退出是允许的；不得为了等待记录消息而延迟通话页释放媒体或返回聊天页。

## 8. 控件定义

| 控件 | 开启 / 默认态 | 关闭 / 禁用态 | 点击后即时反馈 |
|---|---|---|---|
| 接听 | 绿色、白色电话图标 | 请求中降低 15% 亮度并显示进度 | 立即停铃、两键锁定、状态变“正在接通…” |
| 拒绝 | 红色、白色挂断图标 | 接听请求中禁用 | 立即播放结束音并关闭本地页，复用现有终结流程 |
| 取消 / 挂断 | 红色、白色挂断图标 | 终结中禁用 | 首次点击立即释放页面交互，防重复提交 |
| 麦克风 | 半透明深底、白色 `mic` | 浅底、深色 `mic_off` | 操作成功后再确认状态；操作中按钮局部 loading |
| 扬声器 | 半透明深底、白色 `volume_up` | 浅底、深色听筒图标 | 同上；Web 无真实控制则隐藏 |
| 摄像头 | 半透明深底、白色 `videocam` | 浅底、深色 `videocam_off` | 关闭后本地画面变头像占位 |
| 翻转 | 半透明深底、白色 `cameraswitch` | 摄像头关闭时 38% 透明且不可点 | 成功后结束 loading，不改变按钮位置 |

所有按钮应由一个 `CallControlButton` 组件渲染，统一处理：尺寸、标签、语义描述、按压态、loading、disabled、开关色彩和防重复点击。

### 8.1 控制顺序不得随状态随机变化

| 场景 | 从左到右 / 从上到下 |
|---|---|
| 来电 | 拒绝、接听 |
| 单聊语音等待 | 麦克风、取消、扬声器 |
| 单聊语音接通 | 麦克风、挂断、扬声器 |
| 单聊视频等待 | 麦克风、摄像头、翻转；下一行取消 |
| 单聊视频接通 | 麦克风、摄像头、翻转；下一行挂断 |
| 群语音 owner | 麦克风、结束通话、扬声器 |
| 群语音受邀成员 | 麦克风、退出通话、扬声器 |
| 群视频 | 麦克风、摄像头、翻转；右侧或下一行结束 / 退出 |

- 等待与接通切换时，麦克风和扬声器位置保持不动，只把中央“取消”改为“挂断”。
- “结束通话”和“退出通话”使用相同红色图标，但 Semantics 和文字不同。
- 禁用按钮不从布局消失；唯独平台不支持的扬声器按钮从一开始就不渲染，避免通话中布局跳动。

### 8.2 操作失败反馈

- 设备开关失败：按钮回滚到真实状态，在控制区上方显示“麦克风操作失败”“摄像头操作失败”等 2 秒短提示；通话继续。
- 接听失败：停止铃声、释放媒体、显示“接听失败”结束层后退出。
- 挂断请求失败：本地仍立即释放并退出，debug 日志保留请求失败；不能把用户留在通话页。
- 群成员退出失败：本地仍释放媒体；服务端由既有状态收敛机制处理，不自动重新进入房间。
- 同一个按钮 operation 未完成前忽略重复点击；不同按钮可否并行应保守处理，摄像头切换与翻转互斥，挂断始终拥有最高优先级。

## 9. 状态文案规范

### 9.1 正常状态

| 场景 | 文案 |
|---|---|
| 语音来电 | `邀请你语音通话` |
| 视频来电 | `邀请你视频通话` |
| 发起中 | `正在呼叫…` |
| 媒体已连接、对方未加入 | `等待对方接听…` |
| 接听提交中 | `正在接通…` |
| 恢复页面 | `正在恢复通话…` |
| 已接通 | 只显示计时 |
| 群聊等待 | `等待成员加入…` |
| 群聊已接通 | `N 人通话中` + 计时 |

### 9.2 弱网与错误映射

| 内部情况 | 用户文案 | UI 形式 |
|---|---|---|
| `reconnecting` | `网络不稳定，正在恢复…` | 顶部黄色半透明状态条，不遮挡挂断 |
| 重连成功 | `网络已恢复` | 绿色 / 白色轻提示，1.5 秒淡出 |
| 重连超时 | `网络连接中断，通话已结束` | 居中短提示，随后关闭 |
| 权限被拒绝 | `无法使用麦克风` / `无法使用摄像头和麦克风` | 原页面说明；不展示异常对象 |
| 对方拒绝 | `对方已拒绝` | 结束短提示 |
| 对方无应答 | `对方无应答` | 结束短提示 |
| 对方结束 | `对方已挂断` | 结束短提示 |
| 本地媒体建立失败 | `通话连接失败，请稍后重试` | 结束短提示 |
| 单聊目标忙线 | `对方正在通话中` | 发起入口轻提示；不进入通话页 |
| 群创建时所选成员忙线 | `所选成员正在通话中，请稍后重试` | 成员选择页轻提示；不得暴露 userId |
| 未知操作失败 | `操作失败，请重试` | 控件上方短提示，不展开技术细节 |

错误映射属于展示层职责。controller 可以保留日志中的完整异常，但页面只读取结构化错误类型或通过纯函数映射为文案。若暂时不能调整错误模型，首版至少在 page 内对常见错误前缀分类，禁止原样渲染 `_controller.error`。

现有事件 reason 的最低映射要求：

| reason / event | 主叫端 | 被叫端 / 其他群成员 |
|---|---|---|
| `call.rejected` / `REJECT` | `对方已拒绝` | `已拒绝` |
| `call.cancelled` / `CANCEL` | `已取消` | `对方已取消` |
| `call.ended` / `HANGUP` | `通话已结束` | `对方已挂断`，若 actor 是本人则 `通话已结束` |
| `call.timeout` / `TIMEOUT` | `对方无应答` | `未接听` |
| `call.group_ended` | `群通话已结束` | `群通话已结束` |
| `NO_PARTICIPANTS` | `群通话已结束` | `群通话已结束` |
| `MAX_DURATION` | `通话时长已达上限，通话已结束` | 同左 |
| accepted device mismatch | `通话已在其他设备接听` | 同左 |

若事件没有 actorId 传到 Flutter，不能可靠区分“本人 / 对方”时先使用中性文案“通话已结束”；不得猜错主体。

## 10. 动效与反馈

- 页面进入：180ms 淡入；不使用大幅缩放。
- 来电按钮按下：80ms 缩放至 0.94，松开 120ms 恢复。
- 接听到通话控制：200～240ms `AnimatedSwitcher` 淡入淡出。
- 本地小窗出现：200ms 淡入，不从屏幕外飞入。
- 网格成员变化：180ms 淡入；不对整个网格重排做夸张动画。
- 弱网条：从安全区顶部 12dp 淡入，恢复后 1.5 秒淡出。
- 挂断：立即锁定按钮并播放现有结束音，页面在现有本地释放流程中退出；不等待服务端响应后才给反馈。
- 触觉反馈只使用系统轻触反馈，且仅用于接听、拒绝、挂断三个关键动作；Web 无触觉反馈。

## 12. 全链路逐文件实施清单

### 12.1 角色、阶段与现有接口语义

UI 文案与业务 endpoint 必须分开定义。页面展示“取消”不代表可以随意改用 `/cancel`；最终调用以 controller 的权威阶段和角色为准。

| 角色与阶段 | UI 红色按钮 | 现有动作 | 服务端效果 |
|---|---|---|---|
| 单聊主叫，等待接听 | `取消` | `controller.hangup()` → `/hangup` | 服务端对 RINGING 按取消收敛 |
| 单聊主叫 / 被叫，已接通 | `挂断` | `/hangup` | 结束整场单聊 |
| 单聊被叫，未接听 | `拒绝` | `/reject` | 结束本次单聊邀请 |
| 群主叫 owner，等待或已有人加入 | `结束通话` | `/hangup` | 结束整场群通话 |
| 群受邀成员，未接听 | `拒绝` | `/reject` | 只拒绝自己的邀请 |
| 群受邀成员，已加入 | `退出通话` | `/group/leave` | 只离开自己；其他成员继续 |
| 来电接听在服务端成功、媒体失败 | 不再显示按钮 | 单聊 `/hangup`；群成员 `/group/leave` | 清理已推进的业务状态 |
| 去电创建成功、媒体失败 | 不再显示按钮 | `/cancel` 补偿 | 清理未接通邀请 |

实施时不得在 widget 内重新拼 endpoint；widget 只调用 controller 暴露的语义动作。

### 12.6 Controller 与媒体设备状态

#### `lib/features/im/call/presentation/controllers/livekit_call_controller.dart`

保持不变：HTTP 业务状态权威、LiveKit 只管理媒体、失败补偿 endpoint、30 秒响铃超时、15 秒重连超时。

用户退出与媒体失败补偿所选 endpoint 必须以明确角色为准：

```dart
final endpoint = args.isGroupCall
    ? (args.isGroupOwner == true
        ? '/system/im/call/hangup'
        : '/system/im/call/group/leave')
    : '/system/im/call/hangup';
```

- outgoing 群 owner、从 `/active` 恢复的群 owner 都走 `/hangup`，按钮均为“结束通话”。
- incoming / restore 的普通群成员走 `/group/leave`，按钮为“退出通话”。
- `_terminateFailedMediaSession()`、`restore()` 在 `/connection` 成功后的媒体连接失败等补偿路径，与主动退出使用同一个角色判定函数；禁止再出现 `entryMode != outgoing` 即 leave 的分支，也禁止恢复失败只本地退出而把服务端会话留在 `CONNECTED`。

需要提供给 UI 的只读事实：

```dart
bool get hasLocalParticipant;
bool get speakerRoutingSupported => !kIsWeb;
bool get usingFrontCamera;
List<CallParticipantMediaState> get participantMediaStates; // 或由 page adapter 构造
CallFailure? get failure; // 面向 UI 的类型，不包含异常全文
```

设备操作要修正为“成功后提交 UI 状态，失败时回滚”：

- 当前麦克风 / 摄像头先反转 bool 再 await；若 SDK 失败会形成假状态。应保存旧值，操作成功后提交，或 catch 后回滚并通知。
- `toggleSpeaker()` 在 Web 不执行，也不允许改变 `_speakerEnabled`。
- 视频通话移动端进入房间后可设置扬声器优先；语音通话保持听筒优先。耳机 / 蓝牙存在时尊重系统路由。
- `switchCamera()` 仅在本地 camera track 存在且 camera enabled 时可用。
- 不把 `connecting` 当作设备可操作状态。

终态应结构化，例如：

```dart
enum CallEndDisplayReason {
  localCancel,
  localHangup,
  remoteReject,
  remoteCancel,
  remoteHangup,
  noAnswer,
  otherDeviceAccepted,
  networkLost,
  maxDuration,
  groupEnded,
  failed,
}
```

日志仍保留完整异常；UI 只消费枚举与可控短文案。

### 12.7 头像与群成员资料

#### `lib/shared/widgets/app_avatar.dart`

- 直接复用，不复制新的头像下载 / 缓存实现。
- 通话页用圆形头像时设置 `borderRadius = size / 2`；群成员网格可使用 12dp 圆角方形或圆形，但全页一致。

#### `lib/shared/widgets/group_avatar.dart`

- 群头像数据已经存在时复用；无成员头像时按群名生成稳定回退。
- 不允许进入通话页后等待群头像网络请求才能展示控制按钮。

#### `groupMembersFutureProvider`

- 群视频用 identity → userId 映射现有成员资料。
- provider 加载前先显示 userId 对应的稳定色块与“成员”占位；加载后只更新名称 / 头像，不改变格位排序。
- 加载失败不在通话页弹错误框，也不影响媒体。

### 12.8 铃声、原生资源与平台配置

#### `lib/features/im/call/infrastructure/call_audio_cue_service.dart`

保留双播放器、循环铃声、结束音去重和 stop-before-end。UI 调用时序固定：

- 前台来电页或去电拿到 callId：开始铃声；
- 用户点击接听：立即停铃；
- `answered` / remote participant 出现：幂等停铃；
- 拒绝、取消、挂断、远端终态：播放一次结束音；
- 弱网重连期间不重新播放铃声。

#### `lib/app/config/app_config.dart`、`pubspec.yaml`

- 继续使用 `assets/sounds/call_ringtone.mp3` 与 `assets/sounds/call_end.mp3`。
- 保持 `assets/sounds/` 已声明，UI 重构不引入第二套资源路径。

#### `android/app/build.gradle.kts`

- 已从同一 `call_ringtone.mp3` 生成 Android native raw resource，保持单一音源。
- UI 改动后仍需验证 debug / release 构建均包含生成资源。

#### `ios/Runner/Info.plist` 与原生配置

- 保持 microphone、camera、audio/voip background mode。
- 当前 native gateway 的 iOS `ringtonePath` 使用系统默认音；若产品要求 iOS 系统来电也使用项目铃声，需要单独确认插件支持的 bundle 资源格式。这属于资源一致性修正，不在 UI widget 内处理。

### 12.9 服务端与推送链路

#### `AppCallController.java`

- create / accept / reject / hangup / group-leave / state / active endpoint 语义不变。
- `/active` 已返回 caller name/avatar；如本地缓存无法稳定取得群名，可向该 VO 增加可空 `groupName/groupAvatar`，仅作展示元数据且保持向后兼容。
- Controller 返回的异常仍可用于日志，但 Flutter 不直接展示其完整 message。

#### `ImCallApplicationService.java`

- 单聊 invite 已包含 `callerProfile.displayName/avatarUrl`，无需新查询。
- 群 join / leave / ended 的业务广播语义保持不变。
- 当前群 owner 通过 `/hangup` 结束整场时广播可能是 `call.ended` 而不是 `call.group_ended`；Flutter 必须结合 `args.isGroupCall` 映射为“群通话已结束”，不能只看 event type。
- UI 不依赖此层广播媒体开关状态。

#### `GroupCallService.java`

- 群 invite 已有 `callerName/callerAvatar`；如果增加 `groupName/groupAvatar`，应在创建群邀请时一次性填充可选展示字段，不新增独立请求。
- 保持“群成员拒绝只拒绝个人、成员离开只离开个人、最后成员离开结束整场”的语义。

#### `ImCallServiceImpl.java`

- 修正群成员 reject 对全局 `RINGING` 的过度依赖：其他成员已接听后，待处理成员仍应能拒绝自己的 pending invite。
- 不改变直聊 CAS 接听和 acceptedDeviceId 多设备裁决。
- 不改变 owner 才能结束整场群通话的权限约束。

#### `CallEventPublisher.java`

- `isExpiredInvite()` 对 `call.group_invite` 应基于目标 recipient 的 participant 邀请状态判断，而非全局 call state；避免首位成员接听后跳过其余待投递群邀请。
- outbox、事件版本和 after-commit 投递保持不变。

#### `AppCallLiveKitWebhookController.java`

- 无需为 UI 修改；继续只做 webhook 验签和媒体事实日志。

#### `CallPushService.java` 与 `OfflinePushServiceImpl.java`

- 当前 `OfflinePushServiceImpl.pushCallInvite()` 记录日志后返回 `NOT_CONFIGURED`，没有真实 APNs、FCM 或厂商推送投递；本文不得将 App 被杀后的来电写成现有能力或验收通过项。
- 当前系统来电成立范围是：App 在线，或进程仍存活且 WebSocket 事件到达后由 `NativeCallUiGateway` 拉起 Android 全屏来电 / iOS CallKit。
- 将来部署离线推送时，`CallPushService.pushData()` 还需兼容单聊邀请中嵌套的 `callerProfile`，显式生成 `callerName/callerAvatar`；目前仅复制顶层字段会造成离线单聊来电身份丢失。此项记录为未来部署前置条件，不纳入本轮 UI 改造。

#### WebSocket 中间件

- SYSTEM_NOTIFY 承载的 call payload 已足够，协议 message type 无需新增。
- 不通过 WebSocket 传视频轨道、音频设备状态或 token。

## 13. 明确不做

以下项目即使微信当前具备，也不进入本轮需求或验收：

- 通话悬浮窗、画中画、最小化；
- 来电“忽略”或仅静音；
- 通话屏幕锁定 / 双击解锁；
- 视频切语音、语音升视频；
- 美颜、滤镜、背景虚化；
- 屏幕共享、录制、字幕、翻译；
- 通话内文字聊天、表情、礼物；
- 群聊中途邀请、成员管理、主持人能力；
- 网络质量面板、码率 / 分辨率选择；
- 拖动本地小窗、双击切换主辅画面；
- 自定义铃声设置页；
- 新增服务端接口或更换 RTC SDK。

## 15. 验收标准

### 15.1 通用

- [ ] 聊天页与联系人资料页发起单聊时展示同一方式弹层；已有通话时均阻止重复发起，失败均不直出异常。
- [ ] 任意页面均能明确看见通话对象或群名、当前状态、主要操作。
- [ ] 任意按钮均有中文标签，不需要仅凭图标猜测。
- [ ] 所有可点击区域不小于 48×48dp，主按钮为 64dp。
- [ ] 360×800dp 设备无溢出、遮挡或按钮重叠。
- [ ] 刘海、灵动岛、Android 状态栏与底部手势区不遮挡内容。
- [ ] 页面不出现 LiveKit、PeerConnection、HTTP 或异常类名。
- [ ] 操作进行中不能重复提交。
- [ ] 返回手势仍通过现有 hangup / leave 流程释放媒体资源。

### 15.2 单聊语音

- [ ] 来电显示头像、昵称、“邀请你语音通话”、拒绝、接听。
- [ ] 点击接听立刻停铃并显示“正在接通…”，只接听按钮显示进度。
- [ ] 去电等待显示“等待对方接听…”，中央按钮文案为“取消”。
- [ ] 接通后显示从 `00:00` 开始的计时，中央按钮文案为“挂断”。
- [ ] 麦克风和扬声器的 UI 状态与实际状态一致。

### 15.3 单聊视频

- [ ] 来电未接听时不主动采集 / 展示本地摄像头。
- [ ] 去电等待时本地视频可作为主背景。
- [ ] 接通后远端画面全屏、本地画面右上角小窗。
- [ ] 任一方关闭摄像头时显示稳定头像占位，布局不塌陷。
- [ ] 摄像头关闭时翻转按钮不可点击。
- [ ] 设备控制不会因五项单行挤压而误触。

### 15.4 群聊

- [ ] 群来电能显示主叫身份；群名不存在时使用明确降级文案，不显示错误标题。
- [ ] 群成员选择 `确定(0)` 禁用，选满 8 人后有明确提示且可取消已选成员。
- [ ] 群语音显示群名和 LiveKit 房间内实际人数。
- [ ] 群发起者显示“结束通话”，受邀成员显示“退出通话”。
- [ ] 群 owner 经 `/active` 恢复后仍显示“结束通话”并调用 `/hangup`；普通成员恢复后显示“退出通话”并调用 `/group/leave`。
- [ ] 某成员拒绝或退出不会关闭其他成员页面。
- [ ] 群创建遇到成员忙线时留在成员选择页并提示“所选成员正在通话中，请稍后重试”，不显示成员 userId。
- [ ] 群视频将本地与远端统一纳入网格。
- [ ] 1 / 2 / 3 / 4 / 5～9 人分别使用本文指定布局。
- [ ] 成员开关摄像头时格位保持稳定。
- [ ] 5～9 人 3×3 网格不被底部控制区遮挡。
- [ ] 界面没有新增邀请、管理或主持人功能。

### 15.5 异常与生命周期

- [ ] 重连时媒体画面不被错误页替换，顶部显示“网络不稳定，正在恢复…”。
- [ ] 重连恢复后提示自动消失并继续计时。
- [ ] 重连超时、对方拒绝、无应答、对方挂断均显示对应短句并正常关闭。
- [ ] 服务端以 `MAX_DURATION` 结束时显示“通话时长已达上限，通话已结束”。
- [ ] 接听失败不会继续显示“来电中”。
- [ ] 原生接听进入 Flutter 后先显示“正在接通…”，不会提前显示无效设备按钮。
- [ ] `/active` 恢复时显示“正在恢复通话…”，成功后进入正确的单聊 / 群聊状态。
- [ ] 终态先释放媒体，再短暂显示 600～900ms 结束文案。
- [ ] 拒绝、取消、挂断和远端结束均只播放一次结束音。
- [ ] Android、iOS 真机与 Web 分别验证；Web 不展示伪扬声器切换结果。

### 15.6 后台、系统来电与权限

- [ ] 在 App 进程存活且 WebSocket 事件已送达的前提下，Android 锁屏 / 后台来电显示正确名称、类型、拒绝和接听。
- [ ] 在同一前提下，iOS CallKit 接听、拒绝、超时与 Flutter 页面状态一致。
- [ ] 系统拒绝来电不会再打开 Flutter 页。
- [ ] App 回前台不会恢复已结束通话。
- [ ] 去电权限拒绝发生在创建邀请前；来电权限只在点击接听后请求。
- [ ] Web 浏览器拒绝媒体权限后不展示浏览器异常类名。

> 能力边界：终止 App 进程后的离线来电当前不验收为通过。只有完成 `OfflinePushServiceImpl` 的真实推送部署、单聊 caller profile 展平和设备实测后，才能把该场景加入本节。

### 15.7 通话记录闭环

- [ ] 单聊双方对已接通、未接、拒绝、取消、忙线看到的主体和状态准确，时长格式正确。
- [ ] 群通话记录居中展示，任何终态均不出现“加入了群聊”等非通话文案。
- [ ] 当前无回拨行为的记录不呈现可点击态；记录消息晚到不阻塞通话页退出。

## 17. 最终交付判定

本设计完成实施后，用户应获得一种熟悉但不臃肿的通话体验：来电能立刻识别人和类型，接听过程有确定反馈，语音通话围绕头像与计时，视频通话围绕对方画面，所有设备按钮可读且状态真实，弱网和结束都以简短人话反馈。

如果实施中出现“为了看起来像微信”而需要增加新的服务端状态、接口、权限或通话动作，应停止该项并回到本文的“明确不做”范围。本轮成功标准是把已有核心能力做清楚、做稳定、做一致，而不是追齐微信全部功能。
