# 需求文档: 完整的企业级 IM 消息系统

## 简介

本文档规定了一个完整的、高效的、规范的企业级 IM 即时通讯系统的需求。系统基于现有的 WebSocket 中间件 (shengyu-spring-boot-starter-websocket) 构建，该中间件已提供底层的连接管理、协议处理、消息路由等核心能力，支持 50w+ 并发连接。

系统采用以下技术栈:
- **后端**: Spring Boot + Netty WebSocket + Protobuf
- **前端**: uni-app x (UTS 语言)
- **中间件**: shengyu-spring-boot-starter-websocket (已完成)
- **协议**: WebSocket + Protobuf 双协议支持

本系统将实现完整的 IM 功能，包括单聊、群聊、消息类型、消息状态、高级功能、业务通知集成、实时通话、性能优化、多端同步、离线处理等。

### 现有基础设施

**重要**: 以下基础设施已经存在，本需求将基于这些现有功能进行扩展:

1. **数据库表** (已存在于 `sql/mysql/1.0/im/ddl_im_tables.sql`):
   - im_message, im_conversation, im_group, im_group_member
   - im_message_read, im_contact_setting, im_group_invite
   - im_group_file, im_group_folder (群文件功能已实现)

2. **文件上传服务** (已实现):
   - 后端 API: `/app-api/infra/file/upload` (AppFileController)
   - 前端工具: `utils/upload.uts` (统一上传接口)
   - 群文件管理: AppImGroupFileController (群文件专用接口)

3. **角标通知服务** (已实现 - 参见 im-badge-notifications spec):
   - 后端: ImBadgeService (角标数据计算和推送)
   - 前端: BadgeService (services/badge-service.uts)
   - WebSocket: BADGE_UPDATE 消息处理 (messageType = 204)
   - UI 集成: message.uvue, index.uvue, workbench.uvue
   - 功能: 消息角标、菜单角标、多端同步、本地缓存
   - **需求28-30已由此实现满足**

## 术语表

- **IM_System(IM系统)**: 完整的即时通讯系统，包括前端和后端
- **Message_Service(消息服务)**: 处理消息发送、接收、存储的核心服务
- **Conversation_Service(会话服务)**: 管理单聊和群聊会话的服务
- **WebSocket_Middleware(WebSocket中间件)**: 底层通信中间件，提供连接管理和消息路由
- **Chat_Message(聊天消息)**: 用户之间发送的消息，包括文本、图片、语音等
- **System_Notification(系统通知)**: 系统级通知，如审批通知、待办提醒
- **Message_Status(消息状态)**: 消息的状态，包括发送中、已发送、已送达、已读、发送失败
- **Read_Receipt(已读回执)**: 消息已读状态的确认
- **Typing_Indicator(正在输入)**: 显示对方正在输入的状态提示
- **Message_Recall(消息撤回)**: 撤回已发送的消息
- **Message_Forward(消息转发)**: 将消息转发到其他会话
- **Quote_Reply(引用回复)**: 引用某条消息进行回复
- **At_Mention(@提醒)**: 在群聊中提醒特定用户
- **Group_Chat(群聊)**: 多人参与的聊天会话
- **Single_Chat(单聊)**: 一对一的聊天会话
- **Offline_Message(离线消息)**: 用户离线期间收到的消息
- **Multi_Device_Sync(多端同步)**: 多个设备间的数据同步
- **Call_Signal(通话信令)**: 语音/视频通话的信令消息
- **Badge_Count(角标数)**: 显示在应用图标或界面上的未读消息数
- **Message_Search(消息搜索)**: 搜索历史消息的功能
- **Virtual_Scroll(虚拟滚动)**: 大量消息列表的性能优化技术
- **Protobuf_Protocol(Protobuf协议)**: 高性能二进制序列化协议
- **Message_Cache(消息缓存)**: 消息和用户信息的缓存机制

## 需求

### 需求1: 单聊消息发送和接收

**用户故事:** 作为用户，我希望能够发送和接收一对一的聊天消息，以便与其他用户进行私密沟通。

#### 验收标准

1. 当用户发送单聊消息时，IM_System 应通过 WebSocket 将消息发送到服务器
2. 当服务器接收到单聊消息时，Message_Service 应将消息存储到数据库
3. 当接收者在线时，IM_System 应通过 WebSocket 实时推送消息到接收者的所有在线设备
4. 当接收者离线时，Message_Service 应将消息标记为离线消息
5. 当消息发送成功时，IM_System 应更新消息状态为"已发送"
6. 当消息发送失败时，IM_System 应更新消息状态为"发送失败"并提供重试选项

### 需求2: 群聊消息发送和接收

**用户故事:** 作为用户，我希望能够在群组中发送和接收消息，以便与多个用户同时沟通。

#### 验收标准

1. 当用户发送群聊消息时，IM_System 应通过 WebSocket 将消息发送到服务器
2. 当服务器接收到群聊消息时，Message_Service 应将消息存储到数据库
3. 当群成员在线时，IM_System 应通过 WebSocket 推送消息到所有在线群成员的所有设备
4. 当群成员离线时，Message_Service 应将消息标记为离线消息
5. 当群聊消息包含@提醒时，IM_System 应高亮显示被@的用户
6. 当用户被@时，IM_System 应在会话列表中显示特殊标识

### 需求3: 多种消息类型支持

**用户故事:** 作为用户，我希望能够发送多种类型的消息，以便更丰富地表达信息。

**现有基础设施**: 
- 文件上传 API: `/app-api/infra/file/upload` (支持所有文件类型)
- 上传工具: `utils/upload.uts` (提供 uploadFile, chooseAndUploadImage, chooseAndUploadVideo 等方法)

#### 验收标准

1. 当用户发送文本消息时，IM_System 应支持纯文本和表情符号
2. 当用户发送图片消息时，IM_System 应使用现有的 upload.uts 上传图片并发送图片 URL、尺寸和大小
3. 当用户发送语音消息时，IM_System 应使用现有的 upload.uts 上传语音文件并发送语音 URL 和时长
4. 当用户发送视频消息时，IM_System 应使用现有的 upload.uts 上传视频文件并发送视频 URL、封面、时长和尺寸
5. 当用户发送文件消息时，IM_System 应使用现有的 upload.uts 上传文件并发送文件 URL、文件名、大小和类型
6. 当用户发送位置消息时，IM_System 应发送经纬度和地址描述
7. 当用户发送自定义消息时，IM_System 应支持业务模块自定义的消息格式

### 需求4: 消息状态管理

**用户故事:** 作为用户，我希望能够看到消息的发送状态，以便了解消息是否成功送达。

#### 验收标准

1. 当用户发送消息时，IM_System 应立即显示"发送中"状态
2. 当服务器确认接收消息时，IM_System 应更新状态为"已发送"
3. 当接收者的设备接收到消息时，IM_System 应更新状态为"已送达"
4. 当接收者阅读消息时，IM_System 应更新状态为"已读"
5. 当消息发送失败时，IM_System 应显示"发送失败"状态和重试按钮
6. 当用户点击重试时，IM_System 应重新发送失败的消息

### 需求5: 消息已读回执

**用户故事:** 作为用户，我希望能够看到消息的已读状态，以便知道对方是否已经阅读了我的消息。

#### 验收标准

1. 当接收者进入单聊会话时，IM_System 应将该会话的所有未读消息标记为已读
2. 当消息被标记为已读时，IM_System 应通过 WebSocket 发送已读回执到发送者
3. 当发送者接收到已读回执时，IM_System 应更新消息状态为"已读"
4. 当群聊消息被阅读时，IM_System 应记录已读用户列表
5. 当查看群聊消息详情时，IM_System 应显示"X人已读"和已读用户列表
6. 当所有群成员都已读时，IM_System 应显示"全部已读"

### 需求6: 消息撤回功能

**用户故事:** 作为用户，我希望能够撤回刚发送的消息，以便纠正错误或删除不当内容。

#### 验收标准

1. 当用户长按自己发送的消息时，IM_System 应显示"撤回"选项
2. 当消息发送时间在2分钟内时，IM_System 应允许撤回
3. 当消息发送时间超过2分钟时，IM_System 应禁用撤回选项
4. 当用户撤回消息时，IM_System 应将消息标记为已撤回状态
5. 当消息被撤回时，IM_System 应通过 WebSocket 通知接收者
6. 当接收者收到撤回通知时，IM_System 应将消息替换为"对方撤回了一条消息"提示

### 需求7: 消息转发功能

**用户故事:** 作为用户，我希望能够将消息转发给其他人，以便分享有用的信息。

#### 验收标准

1. 当用户长按消息时，IM_System 应显示"转发"选项
2. 当用户选择转发时，IM_System 应显示会话选择界面
3. 当用户选择目标会话时，IM_System 应将消息内容复制并发送到目标会话
4. 当转发文本消息时，IM_System 应保留原始文本内容
5. 当转发媒体消息时，IM_System 应保留原始文件 URL 和元数据
6. 当转发消息成功时，IM_System 应显示"已转发"提示

### 需求8: 引用回复功能

**用户故事:** 作为用户，我希望能够引用某条消息进行回复，以便明确回复的上下文。

#### 验收标准

1. 当用户长按消息时，IM_System 应显示"引用"选项
2. 当用户选择引用时，IM_System 应在输入框上方显示被引用消息的预览
3. 当用户发送引用回复时，IM_System 应在消息中包含被引用消息的 ID 和内容摘要
4. 当显示引用回复消息时，IM_System 应在消息气泡中显示被引用消息的预览
5. 当用户点击引用预览时，IM_System 应跳转到被引用的原始消息位置
6. 当被引用的消息已被撤回时，IM_System 应显示"原消息已被撤回"

### 需求9: @提醒功能

**用户故事:** 作为用户，我希望能够在群聊中@特定成员，以便引起他们的注意。

#### 验收标准

1. 当用户在群聊输入框中输入"@"时，IM_System 应显示群成员选择列表
2. 当用户选择群成员时，IM_System 应在输入框中插入"@用户名"
3. 当用户发送包含@的消息时，IM_System 应在消息中标记被@的用户 ID 列表
4. 当群成员被@时，IM_System 应在该成员的会话列表中显示"[有人@我]"标识
5. 当用户输入"@所有人"时，IM_System 应标记为@全体成员
6. 当显示包含@的消息时，IM_System 应高亮显示@的用户名

### 需求10: 正在输入状态

**用户故事:** 作为用户，我希望能够看到对方正在输入的状态，以便知道对方即将回复。

#### 验收标准

1. 当用户在单聊输入框中输入文字时，IM_System 应发送"正在输入"状态到对方
2. 当用户停止输入超过3秒时，IM_System 应发送"停止输入"状态到对方
3. 当接收到"正在输入"状态时，IM_System 应在聊天界面顶部显示"对方正在输入..."
4. 当接收到"停止输入"状态时，IM_System 应隐藏"正在输入"提示
5. 当用户发送消息时，IM_System 应立即发送"停止输入"状态
6. 当群聊中有人输入时，IM_System 应显示"XXX正在输入..."

### 需求11: 消息搜索功能

**用户故事:** 作为用户，我希望能够搜索历史消息，以便快速找到需要的信息。

#### 验收标准

1. 当用户在搜索框输入关键词时，IM_System 应搜索所有会话的历史消息
2. 当搜索结果返回时，IM_System 应按时间倒序显示匹配的消息
3. 当显示搜索结果时，IM_System 应高亮显示匹配的关键词
4. 当用户点击搜索结果时，IM_System 应跳转到该消息所在的会话和位置
5. 当用户按消息类型筛选时，IM_System 应只显示指定类型的消息
6. 当用户按会话筛选时，IM_System 应只显示指定会话的消息

### 需求12: 会话管理

**用户故事:** 作为用户，我希望能够管理我的会话列表，以便组织和查找聊天。

#### 验收标准

1. 当用户收到新消息时，Conversation_Service 应更新会话的最后消息和时间
2. 当用户收到新消息时，Conversation_Service 应将该会话移动到列表顶部
3. 当用户置顶会话时，Conversation_Service 应将会话固定在列表顶部
4. 当用户删除会话时，Conversation_Service 应从列表中移除会话但保留历史消息
5. 当用户设置会话免打扰时，Conversation_Service 应标记该会话并只显示红点不显示数字
6. 当用户清空会话未读数时，Conversation_Service 应将未读数设置为0

### 需求13: 群组管理

**用户故事:** 作为用户，我希望能够创建和管理群组，以便组织多人沟通。

#### 验收标准

1. 当用户创建群组时，IM_System 应允许选择群成员并设置群名称和群头像
2. 当群组创建成功时，IM_System 应为所有群成员创建群聊会话
3. 当用户邀请新成员时，IM_System 应将新成员添加到群组并发送系统消息通知
4. 当用户移除群成员时，IM_System 应将成员从群组移除并发送系统消息通知
5. 当用户退出群组时，IM_System 应将用户从群组移除并发送系统消息通知
6. 当群主解散群组时，IM_System 应删除群组并通知所有成员

### 需求14: 群公告功能

**用户故事:** 作为群主或管理员，我希望能够发布群公告，以便向所有成员传达重要信息。

#### 验收标准

1. 当群主或管理员发布群公告时，IM_System 应将公告内容存储到数据库
2. 当群公告发布时，IM_System 应通过 WebSocket 推送公告通知到所有群成员
3. 当用户进入群聊时，IM_System 应在顶部显示最新的群公告
4. 当用户点击群公告时，IM_System 应显示公告详情和历史公告列表
5. 当群公告更新时，IM_System 应通知所有群成员
6. 当普通成员尝试发布公告时，IM_System 应拒绝操作并提示权限不足

### 需求15: 消息历史加载

**用户故事:** 作为用户，我希望能够查看历史消息，以便回顾之前的聊天内容。

#### 验收标准

1. 当用户进入会话时，IM_System 应加载最近20条消息
2. 当用户向上滚动到顶部时，IM_System 应自动加载更早的消息
3. 当加载历史消息时，IM_System 应显示加载指示器
4. 当没有更多历史消息时，IM_System 应显示"没有更多消息"提示
5. 当历史消息加载失败时，IM_System 应显示错误提示并提供重试选项
6. 当加载历史消息时，IM_System 应保持当前滚动位置不变

### 需求16: 消息时间显示

**用户故事:** 作为用户，我希望能够看到消息的发送时间，以便了解消息的时间顺序。

#### 验收标准

1. 当显示消息时，IM_System 应在相邻消息时间间隔超过5分钟时显示时间戳
2. 当消息是今天发送时，IM_System 应显示时间格式为"HH:mm"
3. 当消息是昨天发送时，IM_System 应显示"昨天 HH:mm"
4. 当消息是本周发送时，IM_System 应显示"星期X HH:mm"
5. 当消息是更早发送时，IM_System 应显示"YYYY-MM-DD HH:mm"
6. 当消息是刚刚发送时，IM_System 应显示"刚刚"

### 需求17: 离线消息处理

**用户故事:** 作为用户，我希望能够接收离线期间的消息，以便不错过任何信息。

#### 验收标准

1. 当用户离线时，Message_Service 应将发送给该用户的消息存储为离线消息
2. 当用户重新上线时，IM_System 应自动拉取离线消息
3. 当拉取离线消息时，IM_System 应按时间顺序插入到会话中
4. 当离线消息数量较多时，IM_System 应分批拉取避免阻塞
5. 当拉取离线消息完成时，IM_System 应更新会话的未读数
6. 当离线消息拉取失败时，IM_System 应提供重试机制

### 需求18: 离线推送通知

**用户故事:** 作为用户，我希望在离线时能够收到推送通知，以便及时了解新消息。

#### 验收标准

1. 当用户离线且收到新消息时，IM_System 应通过第三方推送服务发送通知
2. 当推送通知时，IM_System 应包含发送者名称和消息内容摘要
3. 当用户点击推送通知时，IM_System 应打开应用并跳转到对应会话
4. 当用户设置会话免打扰时，IM_System 不应发送该会话的推送通知
5. 当推送失败时，IM_System 应记录失败日志但不影响消息存储
6. 当用户在其他设备已读消息时，IM_System 应取消该消息的推送通知

### 需求19: 多端消息同步

**用户故事:** 作为用户，我希望在多个设备间同步消息，以便在任何设备上都能看到完整的聊天记录。

#### 验收标准

1. 当用户在设备A发送消息时，IM_System 应实时推送到设备B
2. 当用户在设备A阅读消息时，IM_System 应同步已读状态到设备B
3. 当用户在设备A删除会话时，IM_System 应同步删除操作到设备B
4. 当用户在设备A置顶会话时，IM_System 应同步置顶状态到设备B
5. 当用户在设备A设置免打扰时，IM_System 应同步免打扰设置到设备B
6. 当设备B离线后重新上线时，IM_System 应增量同步期间的所有变更

### 需求20: 多端登录管理

**用户故事:** 作为用户，我希望能够在多个设备上同时登录，以便灵活使用不同设备。

#### 验收标准

1. 当用户在新设备登录时，IM_System 应允许手机、平板、电脑同时在线
2. 当用户在同类型设备登录时，IM_System 应踢掉旧设备并显示"您的账号在其他设备登录"
3. 当设备被踢下线时，IM_System 应关闭 WebSocket 连接并显示重新登录提示
